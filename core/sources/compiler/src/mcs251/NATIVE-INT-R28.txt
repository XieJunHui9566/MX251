R28：独立可重入 32 位整数运行库
================================
显式启用 --mcs251-native-int-runtime；允许 small/large，stack-auto 可选。
此开关同步启用 native ABI，仅将编译器隐式生成的 _mullong / _divulong /
_modulong / _divslong / _modslong 改为 __reentrant __sdcccall(4)。
使用独立 __m251r4_ 符号；缺少 libnativeint.lib 会链接失败，不静默调用旧库。
其它整数宽度、浮点库和用户函数不会自动变成可重入。

参数 DR4、DR12，返回 DR4，前台/ISR 各有自己的寄存器现场与调用栈。
乘法以三个 16x16 部分积生成完整模 2^32 结果；无静态参数或局部缓存。
无符号除法/取模保留既有 251 原生算法、短除法路径和有界零除数出口，
只换 ABI 入口/出口。有符号包装器按无符号模相反数处理绝对值，保存一字节
符号位到本次调用栈；INT32_MIN 的取负不依赖有符号溢出。
手写入口使用既有调用者临时寄存器 DR16/20/24/28；普通 ISR 必须遵循当前
编译器保存现场的约定。已验证普通 ISR，中断嵌套、NMI/RTOS 不在验收范围内。

运行库直接调用的有界约定：无符号除零商为 0xffffffff、余数为被除数；
有符号包装器再按操作数符号作模相反数，INT32_MIN/-1 返回相同位模式。
这些是显式调用支持函数的测试约定；C 的 /0、%0、INT32_MIN/-1 仍未定义。
测试对普通 C 运算符避开这些输入，直接支持函数测试另行覆盖，不混淆两者。

普通模型下，前台和 ISR 共用的用户函数仍须 __reentrant 或使用 --stack-auto；
不能仅打开此开关就宣称整个应用中断安全。未切换的旧运行库仍有原有约束。
原生浮点运行库 --mcs251-native-runtime 继续要求全链 stack-auto。

交付程序集在 device/lib/mcs251/native-int，原始 GPL 与运行库链接例外保留。
同目录 C 文件解释数值算法，构建脚本优先选择 .asm；C 文件不是自动回退。
四种模型使用同一组纯寄存器/栈入口，四份库归档逐字节一致。
sdcc-integer.py 封装整数配置；sdcc-native.py 封装新浮点+整数配置。
默认 ABI/旧库保持不变，没有修改 IDE 默认工具链或全局环境。

R27 的窄变量分配成本调整曾在本轮试验，CRC 栈访问未减少，未采用。
下一步需区分 SPX 栈访问和真正的 R0/R1 间接寻址需求，再修改分配器。
