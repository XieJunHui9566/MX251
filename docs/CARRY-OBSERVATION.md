# 移位后显式读取 CY 的兼容性

2026-11-13，实现 `c4a9e4f`，分支 `codex/carry-shift-compatibility`。

修复十二项共同存在的 `dat <<= 1; output_bit = CY;` 数据依赖丢失。两个后端均已覆盖，独立实板 **128/128** 组通过。同一编译器重新构建全部 75 项，体积仍按同源 Keil 输入比较：**75/75 ≤120%、65/75 ≤110%**。相对上一统一版，0 项缩小、73 项相同、2 项变大，净增加 23 B。

## 原因与实现

原有 C 中端认为移位结果没有后续数据用途，将其删除，却保留显式 CY 读取；两个后端都收到缺少输入依赖的代码。CY 是 MCS251 核心标志，本轮按绝对位地址 `0xd7` 识别，包括不同声明名称，不按 SDK、工程或函数名匹配。

在通用优化前，取已经采样的移位操作数的移出位，建立显式临时值，并在原 CY 读取之前写回 CY。左移取有效宽度最高位，右移取最低位；需要的数值移位仍按正常规则处理，原 volatile CY 读取也保留。这样死代码删除和后端选择都能看到数据依赖，且不重新读取 volatile 输入。

范围为普通 8/16/32 位整数、常量移位数 1、紧接着显式读取 CY；中间只允许该移位结果的直接赋值。有效宽度采用前端生成的移位宽度，覆盖字节复合赋值。它是 Keil 风格的目标扩展，不是 ISO C 对标志位的承诺。跨调用、其他语句、标签或汇编的任意标志存活，以及多位移位、`_BitInt`，不在本次新增范围。

包含 CY 写入的函数参加已有的整函数后端成本比较，十二项发送循环最终选择更小的字节后端。调用效果分析同时识别数值地址、位别名和 `PSW.7`：它们只写标志，不切换寄存器组。PSW 的寄存器组位及整字节写仍按原规则处理；中断对标志的保存没有删除。这个效果补充消除了初版多保存寄存器带来的额外体积。
