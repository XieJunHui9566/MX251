# 链接阶段的同段近调用与跳转

2026-11-13，实现提交 `ba57047`，父版 `d58d0e4`，分支 `codex/near-transfers`。

## 改动

MX251 原来统一使用四字节 `ECALL` 和三字节返回地址。Keil 的 `ROM(LARGE)` 使用 `LCALL/RET`，同段长跳转使用 `LJMP`。两种返回地址宽度不同，因此不能单独替换调用指令。

本版在编译、函数裁剪、运行库选择和自动 ABI 试选结束后，统一选择近入口及全部调用点：

- 普通 ABI2 最多一个寄存器参数，ABI4 最多两个；仅处理现有类型元数据能够描述的函数。
- 函数没有栈参数、取址入口、不透明汇编或外部尾调用。所有实际引用均为已配对的直接调用；启动、库引用和显式保留入口继续使用原约定。
- 被选入口的全部 `ERET` 改为 `RET`，所有直接调用改为 `LCALL`。函数自己的局部对象、保存寄存器和向其他函数传递的栈参数保持原布局。
- 同一函数内可重定位的长跳转改为 `LJMP`。固定宽度跳转表、相对当前位置的固定偏移、不透明汇编保留原布局。
- 仅在目标 CODE 区间属于同一 64 KiB 段时应用；用户项目归档、未登记的原始汇编入口保留原输出。

编译器补充 ABI4 的类型元数据，没有改变原有普通参数常量传播的适用范围。链接后再次核对每条改动的指令编码、目标地址、RET、完整镜像字节差和中断向量。运行库文件和 SDK 源码没有改变。

实现位于 `core/build/qualified/NearTransfers.ps1`；默认 `AUTO`，可通过 `-NearTransfers OFF` 或 CMake `MX251_NEAR_TRANSFERS=OFF` 关闭。自动叶函数 ABI 子构建延后此阶段，由外层对最终选择执行一次。原输出保存在各构建目录的 `near-baseline/`，最终选择及重定位记录在 `near-transfers.json`。
