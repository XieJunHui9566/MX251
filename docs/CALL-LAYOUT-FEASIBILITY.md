# 调用布局主线：2026-11-09 收益筛选

## 本轮决定

**暂不实施新的全工程 ABI。** 原计划先做寄存器参数原型；进一步找回归档后，发现普通函数自动迁移 ABI4 已做过七轮，完整工程没有明显收益，部分镜像反而增大。本轮补做的是此前缺失的四槽布局模型和最终调用点核算，未重跑旧固件矩阵，也未改 SDK。

四槽相比双槽主要覆盖 TFT；三个 USB 工程几乎没有第三、第四参数可迁移。现有证据支持把四槽作为以后 TFT 的局部候选，不能把它作为解决整个冻结工程集差距的主方案。也不能由此断言 MX251 架构不可行。

本轮没有生成优化候选固件，新增体积达标工程为 **0**，运行时间仍未知。EDATA 修复保持在父提交 `00d4cff`，公开发行版仍为 0.0170-test。

## 找回且不重做的实验

| 归档方向 | 既有结果 | 判断 |

| closed-scalar-abi-v1 | 最终 p078 22967 → 23705 B；p080 23195 → 23195 B；另有 p088 -123 B 未验收 | 不能把“开启已有 ABI4”当作新突破 |

这些是各自历史父版的比较，**不能与当前基线混算或累加**。归档状态及内容哈希保存在 [call-layout-evidence.json](call-layout-evidence.json)。前一份可行性说明没有覆盖这三个关闭方向，本记录修正其“下一步先扩 ABI”的优先级。

## 布局原型和完整镜像核算

只读工具：[tools/research/call_layout.py](../tools/research/call_layout.py)。比较普通 ABI2、已有双槽 ABI4 的运输宽度，以及尚未实现的 `packed8` 提案：

- 使用与 ABI4 相同的 R4–R7、R12–R15 共八字节窗口，不增加 GPR 容量。
- 四个 16 位参数依次占 WR6、WR4、WR14、WR12；字节参数占相应低字节。
- 24/32 位参数占对齐的四字节槽；放不下的参数及之后的参数继续走栈。保留三字节返回地址和原参数宽度，不假设填充后的指针改变外部对象表示。
- 这不是新增 `__sdcccall(5)`，没有生产 ABI、名称修饰或运行库承诺。CODE 指针的宽度统计也不代表其可进入 ABI4。

工具先校验 receipt、HEX 校验和/字节数、冻结源码哈希，再将最终 RST 与 ASM 逐行关联，校验实际指令字节和 ECALL 的最终目标。仅在声明与唯一已链接定义的签名相同、ABI2/bank0 普通入口时核算布局；未配对、特殊入口和未知运输类型单独排除。

对于原有栈参数，核对紧随 CALL 的清栈量，并向前识别相应 PUSH 后缀；控制流、标签、POP 或不明 SP 操作为边界。不把调用保存算作参数，不把未识别的区域当成零成本。已共享到另一基本块的清栈暂不展开。所有数量都是静态站点，**不是运行次数**。

| 工程 | 冻结完整代码 / B | 配对调用 / 全部直接调用 | 参数准备可核对 / 配对调用 | 双槽毛减少 / B | 四槽毛减少 / B | 四槽额外毛减少 / B |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| p078 TFT | 22967 | 228 / 238 | 214 / 228 | 638 | 1200 | 562 |
| p080 TFT | 23195 | 254 / 264 | 242 / 254 | 364 | 940 | 576 |
| p087 USB CDC | 4923 | 81 / 140 | 77 / 81 | 244 | 244 | 0 |
| p091 USB MSC | 6577 | 105 / 185 | 99 / 105 | 282 | 286 | 4 |
| p095 USB/双串口 | 6782 | 116 / 183 | 112 / 116 | 360 | 360 | 0 |

“毛减少”只累计已识别区域中理论可移除的完整 PUSH 指令和全部栈参数消失后的清栈指令。**没有扣新参数搬运、寄存器冲突/溢出和调用保存，没有计算 callee 接收代码及库变化，也未覆盖所有站点。因此既不是完整工程净收益，也不是所有可能收益的严格上界。** 不能把 1200 B 从现有 HEX 体积直接扣掉。

工具还输出逐函数最终机器字节、PUSH/POP 字节、SPX 读写字节、实际调用计数及宽后端拒绝原因，供下一轮直接使用，避免再次从头归因。库内调用没有源级配对资格，已列入排除数。

## 下一项有具体输入的工作

后续优先解决**已有 ABI 下的调用成本与宽后端回退**，先从同时影响多个 USB 工程的路径落点开始，再决定是否重构分配或中间表示。

本轮已定位的最终函数：

- p091 `flash_writesector`：430 B，其中 PUSH/POP 100 B、SPX MOV 133 B，因调用/参数契约回退；`scsi_in/out` 同类回退。先确认精确被拒类型和实际活值，不能仅凭函数名放开准入。
- p087/p095 `uart_set_baud`：495/622 B，语义导入回退；`uart_polling`：315/546 B，内联位操作能力边界回退。后者需要已有目标能力证据，不可为了宽后端强开 SFR 位权限。
- `usb_write_reg` 有 50/61/90 个静态直接调用（p091/p087/p095），自身已在宽后端。新方案必须连同 caller 保存和 callee 破坏集合比较，不能只看 helper 本体几字节。
- p080 `Fill_Triangel`：1316 B，其中 PUSH/POP 168 B、SPX MOV 288 B；`Show_Str`：741 B，其中 164 B、224 B。这里适合检查活跃区间和 spill；不要再次单做寄存器槽数增加。

这只是下一项的定位，不代表这些字节全部可消除。改动分配、emitter 或成本选择时，继续执行 V0.0136 永久负例要求，并以正常入口的完整镜像和逐路径成本决定是否扩大；本轮只读分析没有改动生产成本模型。
