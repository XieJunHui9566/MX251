## 改动与原因

已有窄无符号取负优化会比较完整函数的两种后端实现，但资格检查此前排除了不含有序内联操作的 ABI4 调用。启用原生整数库后，同一函数因此失去原本可用的候选。现在窄取负候选也接受 ABI4，沿用原有完整函数成本选择。

另一处是实参求值：普通 DATA 对象已有 SEND/IPUSH 快照，但原生 ABI4 调用仍一律退出宽后端。现在普通对象复用这份已求值的标量，在 CALL 时完成寄存器或栈参数搬运。两次调用之间被调用函数修改全局对象时，第二次调用重新取值；跨调用活跃值仍由现有调用效果和寄存器保存机制处理。

volatile 实参继续使用原来的 ABI4 发射路径，避免改变多实参和逐字节读取次序。SFR/sbit 在前端已标记为 volatile。没有增加新的调用约定、优化开关或按工程/函数名称选择的规则。
