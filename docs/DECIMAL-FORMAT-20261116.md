# 32 位十进制调查与乘除法寄存器跟踪修复

本轮保留现有十进制算法。五个替代方案在目标机编译后都更大，最小增量仍为 13 B。实际提交的是调查中暴露的通用后端错误：把原生寄存器乘除法误按 AB 指令跟踪，以及 AB 除法的余数计算使用了已被覆盖的被除数。

## 十进制调查

在现存 203 项的格式需求记录中，6 项选用了闭合格式的 32 位十进制转换：p083、p120、p121、p122、p123、g128。p083 已使用 MDU32 除法；其余五项使用软件逐位转换，具有相同的格式化源码、内存模型和私有 ABI 形态。此处统计的是现存需求记录，不是所有用户程序中的调用频率。

软件路径每取一个十进制数字要执行 32 次移位除法，最多十位共 320 次。普通 MCS251 的原生 16 位除法可用于按 256 进制分块处理；现有通用整数库 `_divulong` 已有对应的三次除法路径。因此调查同时检查直接内联算法和复用现有库的成本。

以下是同一个 p120 格式化单元、同一编译器、small 模型、私有 ABI4 的目标代码。包含该单元全部函数；不是完整固件大小。

| 方案 | 指令/B | CODE 常量/B | 合计/B | 相对当前/B |
| --- | ---: | ---: | ---: | ---: |
| 当前逐位算法 | 591 | 0 | 591 | 0 |
| 四字节循环除法 | 604 | 0 | 604 | +13 |
| 高 16 位加两个字节展开 | 622 | 0 | 622 | +31 |
| union 字节数组循环 | 647 | 0 | 647 | +56 |
| 十进制幂表逐位减法 | 634 | 40 | 674 | +83 |
| 移位加法倒数近似及修正 | 739 | 0 | 739 | +148 |

前四个标量形态（当前、四字节、高字加两字节、倒数法）还比较了 small/large × ABI2/ABI4；各模型结论一致。union 和幂表形态比较了 small 下的两种 ABI。共保存 20 个成功的目标编译结果。union 是编译成本试验，未作为已验收的跨字节序算法。

直接调用原生整数库的格式化单元为 ABI2 648 B、ABI4 579 B，单看单元分别少 10/12 B。但它新增了整数库链接依赖，不能把这 12 B 报成固件收益；现有软件格式化实现没有这个外部除法调用。本轮没有为该路线改项目运行库选择。

算法方案均未进入生产生成器，未为被否决的方案继续做全量工程或实板计时。上述循环次数是算法工作量，不是板上耗时或指令周期。

## 通用后端错误与修复

研究中的四字节循环在旧编译器的 ABI4 路径触发 Windows 整数除零异常 `0xc0000094`。GDB 栈为：`_mcs251_rtrackUpdate → emit_raw → emitcode → mcs251GenUnsignedWordDivision → genMod`。即使最终选择宽后端，生成旧后端候选时也会经过这里。

`rtrack.c` 原来只按 `div`/`mul` 助记符前缀匹配，没有区分 AB 与原生寄存器形式，因而使用无关的 A/B 已知值解释 `DIV WR,WR`。当 B 恰好被跟踪为零时，编译器自身执行了除零；非零时也可能保留错误的寄存器事实。

修复将 AB 常量计算限定到精确的 `div ab`、`mul ab`；其他寄存器形式沿既有未跟踪指令路径清除寄存器事实。AB 除法先保存输入，再同时计算商余数，避免先更新 A 后又把商当被除数计算余数。AB 的已知零除数清除结果事实，不在宿主机执行除法。

修改不依赖器件、SDK 文件、格式串或工程编号。运行库生成器及 SDK 源码未改。

## 验证

- 新增主机检查直接编译并执行实际 `rtrack.c`，仅替换编译器周边服务：覆盖全部 256×256 AB 输入的乘法与除法，以及四个原生指令形式，共 131076 组检查。
- 新增独立十进制循环复现用例。旧编译器确实以 `3221225620 / 0xc0000094` 退出；修复后 small/large × ABI2/ABI4 四种配置编译、汇编成功。
- 既有原生窄除法检查通过 8 种内存模型、优化模式、ABI 组合，并覆盖混合位宽、活跃值、volatile、禁用开关及边界降级。
- 完整工程对照和本轮候选的身份、HEX、收据记录在同名 JSON 中。

本轮没有实板执行或运行时间测量，也未重建 Keil、STC-IDE 或全量工程。
