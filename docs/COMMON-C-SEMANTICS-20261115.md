# 窄乘法与弃用 volatile 读取（2026-11-15）

父版 `4e8d192`；实现与测试 `79d88bc`。编译器 SHA-256：`7a76dd66e99474eb7da44d1b56a8a1c8b0e990b457598d868a9167cdfe45858c`。

## 共同原因与实现

父版可构建集合仍有 7 处乘法准入失败、4 处弃用 volatile 读取失败。数字累加中的 `value=value*10+digit` 经前端截断后会形成有符号 8 位乘法；原 MIR 只允许无符号。`port;`、`port|=255` 等写法保留的 DUMMY_READ_VOLATILE 原先只接受位对象，并依赖内联汇编能力开关。

- 低 8/16 位整数积接入现有 WR 乘法：输入按自身类型符号扩展或零扩展到 16 位，取硬件积低位。完整 32 位积仍要求无符号因子；有符号 32 位乘法仍沿用已有运行库路径。
- 新后端独立接入 C 弃用读取，包括位、SFR、DATA、EDATA、XDATA/XIDATA、CODE、可访问栈标量。保留 RIGHT/LEFT 顺序、重复读取、物理字节数和低字节先读顺序，结果不再占用值寄存器。CODE 保留 MOVC。没有扩大为字访问或删除读取。
- 读取参与现有访存屏障；栈对象提升与重排同步维护其对象编号。纯 C 读取不再需要开启内联汇编。
- 编码成本解析接入这些直接内存符号。原字节/字乘法测试同步当前诊断名称；旧字乘法测试中过时的整函数回退和分配形状断言改为当前运行库路径，并与父版 REL 对比。

编译器没有 SDK、工程名、函数名或器件名匹配。官方源文件及构建配置保持一致。未扩大到任意聚合对象、原子对象或所有参数类型；仍受现有 ABI 准入范围约束。
