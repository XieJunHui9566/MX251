# 精确整数／浮点缩放链消除

基于 `63ead71`，分支 `codex/float-format-edata`。开发包位于 `E:/STVAPP/MX251-baseline/development/exact-float-scale/core`。本轮修改 MX251 中间层，SDK 源码和数学运行库源文件保持原样。

## 规则与适用范围

在浮点表达式降低为运行库调用之前，识别同一基本块中相邻的“无符号整数转 float → 常量缩放 → 转整数”。两个浮点临时值都只有一个定义、一个使用；输入读取仍发生在原位置，包括 `volatile` 输入。

输入最多 16 位，正比例常数表示为 `N / 2^s`，`s ≤ 31`。只有输入类型整个范围都满足 `max(x) * N < 2^24`，且取整结果可以放入目标整数类型，才执行替换：

```c
/* x 是 unsigned int，目标为 unsigned int */
(unsigned int)(x * 0.625f)
/* 等价中间运算 */
(unsigned int)(((unsigned long)x * 5UL) >> 3)
```

整数转 binary32 与整数乘积都可精确表示，二的幂次缩放也不引入舍入；非负数转整数的截断因此等价于逻辑右移。中间整数按所需范围选用 16 或 32 位，后续仍经过现有公共优化和后端。除法仅纳入除数为二的幂的情形。

该规则依据类型和数值范围工作，不识别 SDK 工程名、函数名，也不要求新增编译选项。有符号输入、浮点中间值另有用途、可能发生舍入或结果超出目标类型范围的表达式保留原路径。

舍入边界确实影响结果。例如 `65109 * (259.0f/1024)` 的精确值是 `16467.9990234375`，binary32 舍入后转整数为 `16468`，直接整数乘移位则为 `16467`。测试包含这类反例，避免把所有二进制分数一概替换。

## 五项数学例程

五项 × 两种运行库的 10 次构建全部完成，全部 SDK 输入文件与上一轮逐字节相同。统计完整 HEX 有效字节数；每项采用 standard/native-math 中较小的结果。Keil 对照沿用上一轮相同源输入的构建。

| 工程 | 上轮/B | 本轮/B | 减少/B | Keil/B | 本轮/Keil | 运行库 |
|---|---:|---:|---:|---:|---:|---|
| p041 | 2844 | 2844 | 0 | 2582 | 110.15% | native |
| p076 | 19323 | 19323 | 0 | 19918 | 97.01% | standard |
| p077 | 19285 | 19285 | 0 | 19921 | 96.81% | standard |
| p079 | 18764 | 18764 | 0 | 19556 | 95.95% | standard |
| p081 | 3505 | 2893 | 612 | 2806 | 103.10% | native |

合计 **63721 → 63109 B，减少 612 B**。五项中 **5/5 ≤ Keil 120%，4/5 ≤ Keil 110%**；p041 仍为 110.15%。

p081 的 native-math 版本减少 **17.46%**，从 Keil 的 124.91% 降为 **103.10%**；standard 版本则从 **8101 → 4736 B**。其余四项两种运行库配置的体积都与上一轮相同。

## p081 收益来源

温度换算中的两处 `0.625` 缩放都符合规则，源码未改。最终 `_ReadTemperature` 从 **209 → 163 B**；其余 CSEG 从 **2365 → 1799 B**，`_fsmul.rel`、`_fs2uint.rel`、`_fs2ulong.rel` 退出链接。合计 **612 B**，常量、启动和向量占用不变。

用于打印的 `(float)Temp / 10` 仍保留浮点除法。原 unsigned-int 到浮点的转换仍用于这条实际路径。

- 16 类编译检查分别覆盖 legacy、ordinary-wide 后端，共 **32 项通过**。包含换序乘法、8/16 位输入、32 位结果、有符号结果、二的幂除法、极小比例、volatile 自增，以及舍入、范围和共享浮点值等边界。
- 六个比例遍历全部 65536 个输入，使用独立 binary32 舍入模型进行 **393216 次比较**，全部一致。
