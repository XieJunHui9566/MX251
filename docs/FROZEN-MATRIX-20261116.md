## 后续工作的收敛点

正常可比工程到110%的超额合计为 10994 B，到120%为 2160 B。上面五项占120%超额的 1525 B（70.6%）。这些是逐工程目标缺口，不是已证明能删除的指令量。

- 先统一处理 printf/puts 的共享库成本，解决本次出现的成组增长；采用完整程序净收益作为选择依据。
- 主要优化范围集中于 FFT 的活值/地址分配、USB 控制流程，以及 PWM 等内存标量运算。p127 的 main 仍因调用接口契约降级；g139 的 ISR 能进入 wide，但496 B大于旧后端339 B。两类原因分别处理，不能用“已支持新后端”代替代码质量指标。
- 先用上述代表函数与独立用户程序证明同一机制有足够收益，再统一完成一次整包验收。已有地址与调用研究继续沿用；本轮没有重新实现优化，也没有启动下一轮编译器修改。
