# 通用优化再筛选：调用、指令效果与 CODE 读取

第二项中的 ISR 保存部分已完成，见 [外设位操作参与中断保存精简](ISR-PERIPHERAL-BITS.md)。普通函数的指令效果贯通仍是后续方向。

第一项已接入通用构建选择器，实现和统一工程结果见 [非叶函数自动寄存器传参](SELECTIVE-CALL-ABI.md)。下文保留实施前的研究证据。

2026-11-10，基线 `01d02a9`，分支 `codex/general-optimization-study`。本轮先研究，编译器实现和 SDK 源码未改；使用冻结编译器完成两项调用约定体积试验，未下载硬件。正式 75 工程体积达线数保持 61 项 ≤120%、49 项 ≤110%。

下一步优先扩展**按函数成本选择内部寄存器传参**，随后处理**已知位操作的指令效果与中断保存**。CODE 原生读取列为第三项。第一项已有完整镜像净收益，后两项覆盖更广但尚未形成新编译器结果。

## 最新基线透露的共性

重新读取全部 75 工程的最终 ASM/RST/HEX，绑定 1124 个 C 函数、104278 B 应用指令。普通搬运占 49387 B；PUSH/POP 占 9981 B；其他栈访问/调整占 4937 B；调用占 10078 B。这些是现存成本，不能直接视为可删除字节。

剩余差距主要涉及值和参数的运输，以及单个操作导致整函数错过优化。重复增加算术窥孔的收益已小。Keil 的列表显示：高频双参数调用使用寄存器，CODE 字表使用原生字读取；STC 的冻结对比和此前源码研究继续用于参照机制，本轮没有下载新厂商版本或将其原始 HEX 当作同模型成绩。

## 1. 按函数选择内部调用约定：已有净收益

现有 `SelectiveLeafAbi.ps1` 只接受叶函数；工程含非 C 单元时，还会整体停止候选分析。因而一个本可用寄存器传参的高频小函数，只因内部又调用了其他函数，或工程带有向量汇编，就继续使用栈传递第二个参数。

本轮通过已有 `MX251-INTERNAL-ABI4-V2` 接口，在两份独立输出中仅指定一个双参数函数。没有改 C 文件、SDK 算法、编译器二进制或运行库源码。两个工程的源输入哈希与各自基线一致，编译器均为 `6219b66b43a63fc999a1fc7365244624903b16afbdff44819533229c99edd4b3`。

| 工程 | 父版/B | 试验/B | 净减少/B | 试验/Keil | 实际迁移调用点 |
| --- | ---: | ---: | ---: | ---: | ---: |
| p122 | 5230 | 5079 | 151 | 118.59% | 58 |
| p112 | 6058 | 5905 | 153 | 103.52% | 57 |

两例都选中 `LCD_WR_REG16`，属于同一调用模式，不能当成两个独立算法的普适证明。p122 被调函数反而从 25 B 增到 26 B，但调用者 `LCD_Init` 从 669 B 降到 533 B，完整镜像仍净减 151 B；p112 对应为 32→27 B、682→542 B。收益来自整条调用关系，不能只比较被调函数大小。

按“普通 ABI、两个整数参数、至少 16 个最终直接调用点、无本地地址逃逸/不透明/间接标记”扫描，现有样本共有 4 个待检查候选：p078、p112、p113、p122，调用数分别为 58、57、57、58。实际应用还需把汇编和库引用解析到候选函数。这里的 4 项是候选覆盖，不是 4 项已经获益。

实施方向：让现有选择器按候选函数收集调用关系，识别已登记的向量汇编；允许有普通内部调用的函数参加完整镜像成本比较。沿用现有 ABI4 和调用改写反馈，不新建全工程 ABI。生产规则依据类型、引用、调用次数及实际成本，不使用上述函数或工程名称。全量 ABI4 与全量内联已有失败记录，本轮没有重做。

研究试验通过直接构建入口注入契约；常规 CMake 入口会清理此环境变量。最早的常规入口副本因此与父版相同，未计作迁移试验。真正生效的两份 receipt 均记录 internalAbi4，最终修饰符号及调用点已绑定到实际机器码。两份固件只取得体积证据，尚无运行验证；p122 的试验跨过 120% 线也不计入正式台账。

## 2. 已知指令效果贯通：覆盖中断与普通函数

109 个 C ISR 中，72 个已使用保存精简，37 个尚未使用。其中 **13 个工程、15 个 ISR** 含数值形式的外设位操作；其入口/出口 PUSH/POP 共 **956 B**。当前 `gen_leaf_isr.c.inc` 在遇到任意 INLINEASM 时直接退出，尚未利用已经可识别的 `clr/setb byte.bit` 效果。

最直接的例子是 p015 的 INT2/3/4：函数体各只有一条清中断使能位指令，MX251 各为 **51 B**，Keil 各为 **8 B**。三者合计相差 129 B。p047 的比较器中断为 63/13 B，p032 的 UART2 中断为 136/83 B。956 B 中包含必需保存，不能全部计作收益。

普通函数侧还有 **34 个工程、57 个函数** 因 `ordered-asm-bit-not-capable` 退出宽后端，现存函数指令合计 5977 B。部分是 EA、串口标志等位操作。应复用统一的寄存器、标志和访存效果描述，让这些操作只在所在位置阻止相关变换；ISR 则按实际被改写的现场保存。映射/执行控制位单独分类，外设事务保持原顺序。

单纯去掉入口判断还不够：机器解析器也会因 PSW 操作拒绝整个输入。本轮将原文本交给既有独立优化器，没有取得额外分支缩短或寄存器变换。因此下一项是补足指令表示和效果传递，而不是重复运行现有 pass。

## 3. CODE 常量读取与地址生成：覆盖 31 个工程

最终应用指令中有 **125 条 MOVC，分布在 31 个工程、42 个函数**。当前宽后端对 CODE 对象仍通过 DPX/A 逐字节读取并拼接；p039/p059 的 `get_temperature` 各为 **418 B**，Keil 为 **251 B**。Keil 列表在字表读取处直接生成 `MOV WR10,@DR4` 一类原生字访问。

应从目标声明的代码地址映射出发，为普通、非 volatile CODE 数据选择原生字节/字读取，再连同索引扩展、基址和高位规范化一起比较成本。这个方向与此前 DATA 结构体字段原型不同；不能直接把 CODE 标记改成 XDATA，也不能把 167 B 函数差额全部归因于读取。

常量乘法也有可补之处：已有强度削减针对 32 位运行库乘法，原生窄乘法仍可能用完整 MUL 来计算 `index * 2`。可与地址生成合并处理，但当前没有足够收益证据把它单列为主线。

## 暂不优先

- 跳转表机器 CFG：当前明确识别到 4 个函数、4 个工程，共 1285 B 函数体。需要维护固定表项跨度，覆盖小于上述方向，后排。
- 重做通用 DATA 字段原型、全量小函数内联或全工程 ABI4：历史实编译收益不足或增大，已有结果继续有效。
- p108 的 7766/1434 B 异常比例：其原始数值向量落点问题在 Keil 输入中同样存在，导致完整格式库回退。它属于已知输入问题，本轮不为追逐这个数改 SDK 或放宽不相关分析。
- 继续追 p103 的最后 1 B：不作为这轮通用优化的选题依据。

## 接续与证据

实施顺序为：候选函数调用约定选择 → 已知指令效果贯通 → CODE 原生读取。先让通用选择器自动得到本轮已测的候选，再补新增调用形态的独立执行验证，最后用统一版本做一次 75 工程验收。已有两份完整体积试验直接保留为研究基线。

完整研究目录为 `E:/STVAPP/MX251-mainline-20261110/general-optimization`。`attribution.json` 保存全部函数及 Keil 段对照；`scan.json` 保存指令分类；`call-candidates.json`、`code-loads.json` 保存覆盖统计；`abi-trials.json` 和 `abi-selected-p112/p122` 保存两份完整镜像、输入和构建命令。[结构化证据](general-optimization-study-evidence.json)绑定上述文件指纹。编译器、SDK 和硬件固件均保持本轮研究前版本。
