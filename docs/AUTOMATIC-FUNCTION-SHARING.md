# 自动函数共享：原 SDK 输入减少 1060 B

2026-11-09。编译器已实现同一编译单元内的函数模板共享，不要求修改 SDK 或添加函数名白名单。使用显式选项 `--mcs251-share-functions`，配合 `--mcs251-function-metadata`；qualified 构建对应 `-FunctionSharing`。默认关闭，常规 Build-CMake 发布路径尚未启用。

完整测量、文件哈希和实板帧记录见 [证据](automatic-function-sharing-evidence.json)。这是编译能力的新增实现，尚不是双 110% 或双 120% 验收结果。

## 完整镜像

| 原工程输入 | 原基线 / B | 开启共享 / B | 减少 / B |
| --- | ---: | ---: | ---: |
| p080 TFT | 23153 | **22093** | **1060（4.58%）** |
| p087 USB CDC | 4769 | 4769 | 0 |
| p091 USB MSC | 6312 | 6312 | 0 |
| p095 USB/双串口 | 6615 | 6615 | 0 |

四项均完成普通构建、调用破坏反馈和函数 GC；GC 没有回退。逐项输入 SHA-256 与原基线相同。没有叠加手工共享源码、`_swap` 内联或选择性 ABI4 试验。

TFT 中三个原字体函数各 648 B，合计 1944 B。新代码为共享主体 716 B，加三个各 56 B 的入口，合计 884 B，恰好解释完整镜像的 1060 B 差额。比前轮手工源码共享的 997 B 多减少 63 B。

Keil C251 的同工程基线为 18071 B，本次体积为其 **122.26%**；距离 120% 体积线还差 408 B，距离 110% 线还差 2215 B。其他三个工程未出现足够大的同形函数族，不能将本次收益表述为所有工程均获益。

## 实现

[function_share.h](../core/sources/compiler/src/mcs251/function_share.h)在普通/宽后端已完成选择后、输出汇编前读取完整函数。初版处理宽后端生成的 ABI2 普通函数：签名、寄存器操作、内存操作、调用目标、栈布局和控制流完全相同，仅源立即数有差异。不同的 CODE 表地址也是源立即数。

每个原公开函数保留独立入口和原调用约定。入口将自己的常量压栈，直接跳到共享主体；没有新增一层 CALL 返回地址，也没有全局选择状态。共享主体在返回前清除这部分空间。栈形参按入口栈深重新定位，原局部槽保留相对布局。字体族有 9 个常量槽，额外使用 22 B 栈；临时寄存器使用 PUSH/POP 保存，不覆盖原活跃值，条件比较后的恢复不修改比较标志。

同一组常量在多个位置使用时复用槽。机器分支在展开后的布局上重新计算距离，超出短跳范围时生成长跳。每次合并要求主体、入口及分支的成本上界比原函数总成本下界至少少 128 B；未知原指令按 1 B 下界，新指令按 6 B 上界计。该门槛针对编译单元中的候选函数；最终收益仍以完成 GC 的整镜像为准。

函数所有权、签名和原调用事实保留，旧的体积/寄存器效果摘要移除。共享标签归属首个函数，其他入口的跳转使链接 GC 保留主体。函数地址的**身份和可区分性**保留，绝对链接地址当然会随代码布局变化。

初版不处理 ABI4、普通后端回退函数、调试编译、ISR、裸函数、不透明汇编、间接控制转移或显式栈地址导出。直接读取 SP/SPH 的 SFR 别名按地址识别。跨编译单元合并和重新分配寄存器不在本轮范围。

## 执行与时间

[独立夹具生成器及主机校验](../tools/research/function_sharing_fixture.py)生成三份普通位图绘制函数和合成字模，使用不同名字，不复制 SDK 字模数据。回调记录每一次窗口设置、像素写入、绘点及其参数；主机按独立字模公式和循环计算期望哈希、调用项数量、最终颜色。

AI8051U-34K64 实板分别执行父版和开启共享的固件，UART 获得 296/295 帧，均覆盖全部 96 组输入。包含三种尺寸、两种绘制模式、缺失/首个/中间/末尾字模、16 位坐标溢出，以及外层绘制尚未返回时再次调用共享函数。所有帧与主机期望一致。三个入口在实际链接镜像中均为不同地址。

Timer0 mode 1、12T 测量同一夹具的绘制及确定性回调，串口发送在计时之外。每个输入取观测帧的中位数：

| 指标 | 共享版 / 父版 |
| --- | ---: |
| 96 组时间合计 | **100.34%** |
| 有字形绘制用例的最大值 | **101.35%** |
| 全部用例的最大值 | **130.50%** |

最大值来自 case 0 的查无字形路径：259 → 338 个 timer tick。绘制回调较重时额外常量装载的占比小；较短扫描路径能清楚看到它的开销。因此保留显式开关，不直接成为默认优化。此处比较的是 MX251 父版与共享版的测试夹具，**不是 Keil 时间对比，也不是完整 TFT 工程的运行时间**。

设备保留共享测试固件；没有恢复旧固件。STC-Link1D 与 UART 均按本轮枚举结果连接。

## 检查与复现

- [指令差分测试](../core/sources/compiler/src/mcs251/tests/check-function-sharing.py)：768 次执行比较寄存器、调用者栈和返回栈深，覆盖 byte/word/dword 常量、算术/比较/逻辑指令、带活跃临时值的分支和循环。10 组不应共享的输入保持原样。
- 编译器 small 模型的生成夹具自动形成 3 个共享入口。large 模型的该夹具原本就在宽后端导入处回退，开启共享后 REL 与父版相同；未声称该样例在 large 模型得到共享。
- 默认关闭时，small/large 两种模型的完整 REL 分别与父版编译器逐字节相同。
- 16 参数 ABI 和烧录协议本轮没有修改，没有重跑上一轮已完成的整套 ABI 检查或 105 工程矩阵。
