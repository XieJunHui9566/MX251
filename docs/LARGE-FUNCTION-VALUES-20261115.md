# 大函数容量与寄存器冲突分析：2026-11-15

独立用户程序 `giant_messy` 从 7,243 B 缩小到 **4,153 B（−42.66%）**，为 Keil C251 的 **105.22%**；同源实板耗时从 Keil 的 102.70% 降到 **100.39%**，64 个输入中最差为 100.58%。这一个测试函数的体积和测量区域耗时均已进入 110% 线。

整套用户测试固件由 11,074 B 降至 **7,984 B（−27.90%）**；Keil 为 6,124 B，因此整套固件仍为 Keil 的 130.37%。其他函数的指令数量与各类指令字节数保持一致。完整工程运行时间尚未验收，STC-IDE 本轮未测。

## 原因与方案

原新后端最多导入 512 个虚拟值。`giant_messy` 是 96 段连续无符号算术，前端优化后需要 578 个值、583 个节点；导入第 513 个值时整函数回退。许多临时值的存活时间很短，容量耗尽不等于同时需要大量寄存器。

当前优化器按虚拟值身份处理类型、定义、支配关系和别名。直接把不同临时值合成一个编号会改变这些分析；动态位集又涉及所有分配候选的复制方式。本轮先采用已经测出收益的有界扩容，保留独立值身份和现有优化规则。

- 值存储上限扩大到 1,024。正常封装项目入口默认选择 **1,024 值 / 2,048 节点**；低层入口原有 128/512 默认值以及显式 128、256、512 配置仍可使用。
- 将寄存器冲突图从“每个节点比较所有值对”，改为对活跃集合、定义集合做位集并运算。保留原 CFG 不动点、分支和跳转表边，以及既有冲突边；去掉自冲突。
- 不改变对象数、参数 ABI、节点上限及候选搜索预算。超过上限仍会说明原因并回退。176 段的测试在第 1,025 个值处继续触发容量限制；尚未实现无限容量或局部回退。

实现不识别器件名、SDK 路径或测试函数名。程序算法和输入均未修改。

## 编译成本与代码变化

通用大函数探针分别覆盖 ABI2/ABI4、small-size、small-speed、large-size。六种配置均进入新后端并缩小；显式保留 512 上限时，REL 与旧编译器完全一致。

| 探针配置 | 旧编译耗时 | 新编译耗时 | 旧代码 | 新代码 |
|---|---:|---:|---:|---:|
| ABI2 small size | 2.98 s | 3.29 s | 11,527 B | 4,149 B |
| ABI2 small speed | 2.03 s | 2.38 s | 5,872 B | 4,149 B |
| ABI2 large size | 2.93 s | 3.36 s | 11,527 B | 4,149 B |
| ABI4 small size | 1.28 s | 1.63 s | 6,416 B | 4,127 B |
| ABI4 small speed | 1.27 s | 1.61 s | 6,416 B | 4,127 B |
| ABI4 large size | 1.25 s | 1.61 s | 6,416 B | 4,127 B |

每项为一次独立进程的观测值，包含前端与汇编。新后端接纳这些大函数后，进程峰值工作集约 167 MiB，旧版回退时约 65～71 MiB。单个 MIR 候选存储为 4,888,320 B；仍使用整体复制。探针与板上 `giant_messy` 的初始累加值不同，表中代码体积不与板上函数混用。

板上 `giant_messy` 的实际指令从 3,428 条降到 1,738 条。原函数的 189 次辅助调用和 2,280 B 栈操作消失，寄存器搬运由 1,445 B 降至 398 B。Keil 对应函数为 1,733 条指令、3,947 B。上述栈操作包含调用传参与保存，不全是寄存器溢出。

## 验证

- `liveness-sets.c`：84 种控制流图，覆盖 0～1,024 个值、位集边界、循环、重复跳转表目标和已有冲突边；新算法与逐值对算法的结果完全相同，重复计算保持一致。
- `check-wide-capacity.py`：六种大函数配置通过；旧容量生成代码保持相同；值容量与节点容量超限均正确报告并完成旧后端编译。
- 原有用户压力测试：63 个编译单元通过，三种目标描述下纯 C 的 REL 相同；与上一版的全部 63 个 REL 逐字节一致。这组使用既有 128/512 容量，验证原有代码路径。
- 完整测试固件经正常封装入口构建，receipt 确认为 1024/2048。AI8051U 实板取得 3,656 帧，覆盖 **832 个结果**，每项至少四次采样，零错误、零计时溢出。768 项为 12 类工作负载 × 64 输入，另 64 项为空控制。
- 复用同源、同板、同设置的 Keil 固件及原始采样。Timer0 测量区域包括分发、工作负载和结果搬运，不含 UART；按烧录时测得时钟归一化。空控制未扣除，也不计入达线数量。耗时全输入通过 110% 的类型仍为 **6/12**。
- 扫描已有 97 工程证据中的 359 份最终 ASM，未发现值/节点容量拒绝。本轮没有重跑官方全矩阵，也没有更新其达线数量。
