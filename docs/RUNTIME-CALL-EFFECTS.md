# 通用算术与运行库调用分析

2026-11-09，父提交 `2d163a0`，分支 `codex/runtime-call-effects`。实现提交 `8ebb85d`、`e51d330`，独立测试程序 `d8de004`。完整数据见 [runtime-call-effects-evidence.json](runtime-call-effects-evidence.json)。

改动属于 MX251 编译器和配套构建流程。优化条件只有机器指令、函数 ABI、调用关系与实际运行库内容；没有 SDK 工程名、应用函数名或目录匹配。七个完整工程的输入前后哈希一致，SDK 源码没有修改。

## 实现

共同指令分析现在认识 `MUL/DIV Rn,Rm`、`MUL/DIV WRn,WRm` 及 `AB` 形式，读集合按两个输入计算，写集合覆盖包含目标的整个 word/dword。隐式结果的另一半不能作为普通显式操作数重命名。规则依据 [TSC80251 Programmer’s Guide](https://www.keil.com/dd/docs/datashts/atmel/tsc251pg.pdf) 的 DIV、MUL 指令定义，适用于两个后端。

调用反馈同时支持 ABI2、ABI4，并将库函数与应用函数放入同一调用图。`RuntimeCallEffects.json` 描述本版原生整数库的五个成员。生成工具重新汇编源文件，逐个核对 REL 内容与实际归档成员完全一致，然后从指令推导局部写集合；调用者使用的是包含被调函数依赖的完整集合。应用自行定义库符号时，以应用定义为准；库内调用也重新解析到该定义。

另一个覆盖问题是调用发现曾随写集合分析一起提前结束：例如遇到间接内存写入后，后面的直接调用没有进入反馈重编译名单。现在先收集完整函数内的直接调用，再计算写集合。调用者自身的写集合未知，不再阻止它使用其他被调函数的已知寄存器信息。

运行库摘要随 `-MachineIr -NativeIntegerRuntime` 接入已有构建入口，也支持既有 `runtime=native-int` 配置。没有新增用户开关。摘要与归档 SHA-256 绑定；更换库后需重新生成摘要。当前只接入配套原生整数库，不宣称已支持任意第三方库或工程归档。应用公开 ABI 未改变。

## 不依赖 SDK 的实板验证

新增 `tests/runtime-arithmetic.c`，两个可移植 C 工作负载分别执行无符号乘除余流水计算和有符号定点校准运算。只复用既有计时/UART 测试外壳，算术程序不包含器件或 SDK 接口。独立 Python 模型按 32 位无符号回绕、有符号除法向零截断计算结果。

AI8051U、40 MHz、Timer0 /12T、115200 UART；每种工作负载 64 个输入，多次采样取每例中位数后累加。父版和新版都开启 MachineIr + Native。

| 工作负载 | 父版 tick | 新版 tick | 时间减少 |
| --- | ---: | ---: | ---: |
| 无符号乘除余流水 | 38592 | 37375 | 3.15% |
| 有符号定点校准 | 55610 | 54563.5 | 1.88% |

测试完整固件 **1577 → 1503 B（−4.69%）**。两份固件各 128 例结果通过，分别采集 568/573 帧。原三角形与字节控制流测试继续通过 128 例；三角形 tick 从上轮 11071 降为 **10747（−2.93%）**，字节控制流 10163 不变。三角形相对原有已通过的 Keil 内核计时为 125.40%，仍未过 110%。测试板保留本轮三角形测试固件。

本轮另编译了新增算术测试的 Keil C251 5.60 版本，但实板首个无符号用例得到 `8a46fdea`，参考模型为 `c59e1c04`。尚未定位这份测试/参考差异，原始串口与固件已保存；不使用其体积/时间作达标分母，也不据此判断 Keil 或芯片有问题。此前三角形 Keil 数据不受这一新增测试结论影响。
