# 循环地址生成与分支共有代码：实施前研究

2026-11-10，基线 `077b1a6`，分支 `codex/loop-tail-feasibility`。结论：**先做多路循环游标，再做分支参数汇合与尾部共享**。现有 typed MIR、CFG、重新分配和整函数候选计价接口能够承载这两项。

本轮研究 75 项最终 ASM/RST/HEX，对照冻结 Keil 列表；使用现有编译器导出 3 个单元的 MIR，现有汇编器测量 4 个独立片段的编码。没有修改编译器、构建流程、SDK 或运行库，没有生成新的推荐核心或进行硬件下载。体积状态保持 **68/75 ≤120%、53/75 ≤110%**，完整工程时间未测。推荐核心仍为 [上一轮版本](SCALAR-LITERAL-CONVERSIONS.md)。

## 覆盖面

统计脚本把每条指令与最终 HEX 字节对应，再根据控制流支配关系识别循环。分支候选只允许立即数 MOV 不同，其余指令、寄存器与终点相同，每个函数取一组不重叠尾部。

| 项目 | 结果 | 含义 |
| --- | ---: | --- |
| 最终代码中的固定形态地址重算 | 72 处 | 复制基址、扩展索引、相加、24 位掩码 |
| 位于自然循环内 | 56 处，26 工程、35 函数 | 这 56 段当前共占 672 B |
| 循环内没有调用 | 31 处，12 工程 | 适合作为首批进一步检查的范围 |
| 带立即数差异的相似尾部 | 11 工程、15 函数 | 各函数最大一组，不重复叠加重叠候选 |
| 上述尾部内重复的完全相同指令 | 433 B | 已排除不同立即数的 MOV，尚未减新增跳转及参数运输 |

这些是当前代码和候选覆盖量，**不是可节省字节总数**。循环是否可递推、寄存器是否够用，仍由实际 MIR 变换与候选计价决定。扫描还没有包含所有寻址形态或寄存器不同的同构尾部，因此也不是上限。

## 一、循环游标：先去掉每轮地址重算

代表性的现状：

| 工程/函数 | MX251/B | Keil/B | 循环中的被识别地址重算/B |
| --- | ---: | ---: | ---: |
| p074 / main | 323 | 229 | 96 |
| p134 / LoadSPI | 191 | 134 | 60 |
| p039 / get_temperature | 334 | 251 | 24 |
| p059 / get_temperature | 334 | 251 | 24 |

p074 有两个 16 次循环，每轮从两个 CODE 字节表复制到两个 XDATA 数组。四个基址已经提前装好，循环内却各自再执行：

```asm
mov  dr0,dr12
movz wr22,r9
sub  wr20,wr20
add  dr0,dr20
anl  wr0,#0x00ff
```

每段实际 12 B。读取 CODE 字节又经过 `MOV DPX`、`CLR A`、`MOVC` 和结果搬运，共 6 B。Keil 的这份代码**仍按索引生成地址**，但使用更紧凑的地址组合和 `MOV R11,@DR` 直接读字节；不能把它说成已经做了循环游标变换。

本轮提出的游标方案：保留原循环计数和退出条件，把每个地址流改成入口初始化、每轮按步长递增。p074 可以复用当前已占用的四组基址寄存器，保留每次更新后的 24 位掩码。读取和写入顺序仍为第一路读/写、第二路读/写。

独立汇编片段的实测编码如下。它们未链接成固件，也未由新的编译器变换生成：

| 单个循环体，含计数/比较/回跳 | 编码/B | 静态指令条数 |
| --- | ---: | ---: |
| 当前最终指令 | 73 | 33 |
| 游标＋局部 CODE 原生字节读取草案 | 43 | 15 |

两个循环合计有 **60 B 的局部编码空间**。p074 距 120% 线差 59 B，值得作为首个观察点；不能提前记为过线，完整函数的寄存器分配、入口及布局尚未实际生成。保留 MOVC 的纯游标版本按这些现有编码约减少 48 B，因此需要把游标和该区域内的 CODE 字节读取一起计价。

### 现有实现为何没有完成这件事

- `wide_fold_indexed_addresses` 只融合同一直线片段中的地址与单次访问，没有跨迭代递推；CODE 字节访问还被 `width==1` 明确排除。
- `wide_emit.c.inc:wmemory` 对 CODE 字节继续使用 MOVC。这源于 [此前全面启用字节原生读取的工程体积回退](NATIVE-CODE-READS.md)，不能直接全局放开重跑。
- `wide_affine.c.inc` 中已有默认关闭的显式原型，只接特定排列的单路数组填充；要求地址节点在循环体中、只做字面量存储，并排除 CODE 指针。p074 是已提升基址的多路 CODE→XDATA 复制，当前原型不匹配。
- 诊断 MIR 进一步确认：p074 的 CODE 读仍保留独立 `+` 地址节点，而 XDATA 写已经把索引折入访问节点。新分析必须同时认识这两种表示。

### 推荐实现边界

在现有 MIR 候选流程中识别单入口、单回边、无调用的有界循环；识别不变基址、同一递增计数器和各地址步长。第一版处理已知对象与无回卷的索引，保留计数器、访问顺序、内存宽度及 24 位地址规范化。

同时识别独立地址节点和 `addressOp/addressIndex` 已融合的访问。只在选中的循环候选里尝试 CODE 原生字节读取，沿用目标的平坦 CODE 能力；其他字节查表仍走原有选择。随后重新分配寄存器并比较完整函数成本，入口初始化与任何溢出都计入。

先看 p074，再观察 SPI 打包、温度表和 TFT 字符读取。不要把 31 个无调用地址点直接当作全部符合首版规则。

## 二、分支参数汇合：共享操作，让各分支提供值

现有 `gen_cfg_cleanup.c.inc:m251CfgShareTails` 最多向前比较 24 条指令，以完整文本相等为条件。末尾的立即数一旦不同，共有运算就无法继续向前合并。这里缺的是分支值的汇合表示，继续扩大相同文本搜索次数解决不了。

### 首个适合落地的例子：PWM 更新

p051 的 `UpdatePwm` 当前 **208 B**，Keil 为 **187 B**。三个分支各有 62 B、24 条指令的尾部；除两个外设地址常量外，位运算、读取和写入顺序完全相同。

MIR 中这三组各自拥有同形的 `WM_LOAD → 位运算 → WM_STORE → 第二次 WM_STORE`，差异是普通地址操作数的常量。它们是 volatile 字节访问，合并后的公共区域必须保持每条路径原有的一读两写及先后顺序。

可让各分支选择两个地址，转入同一份计算和写入。独立片段保留当前指令形态，使用一个额外字寄存器运输第二个地址：

| 三份尾部区域 | 编码/B |
| --- | ---: |
| 当前三份各 62 B | 186 |
| 分支参数装载＋两条 EJMP＋一份共有尾部 | 88 |

**98 B 是局部片段编码差额**，没有计入实际变换后选择器、重新分配和整体布局的变化，不是完整函数承诺。第一、第二条路径会增加跳转与参数搬运；这一项主要提供体积收益，必须对热点路径一并计价。

### 时钟设置：Keil 的直接证据

p095 的 `SetMCLK` 为 **369/196 B**。Keil 让分支先选择目标频率与校准地址：

- 三条路径跳到 `?C0092`，共用读取校准值、写 IRTRIM/VRTRIM 及部分 IRCBAND 处理。
- 四条路径最后在 `?C0093` 共用写 IRCBAND、恢复分频和更新 MAIN_Fosc。
- 目标频率保留在 DR4，前面的比较和最后的全局写入复用该值。

MX251 则在各条路径重复物化地址和频率常量。扫描器仅对其中两条完全同形的尾部就找到 **58 B 重复相同指令**，但另外两条路径的位操作和终点布局不同，不能直接把 173 B 函数差额全部记成尾部共享收益。

同类候选还出现在 USB 描述符/控制请求和 I2S 主循环。适合先做“类型和操作相同、纯常量操作数不同、终点相同”的 typed MIR 尾部合并，再扩展寄存器不同或控制流更复杂的情形。

### 推荐实现位置

放在寄存器分配之前：比较节点操作、类型、内存属性和控制终点；为不同常量创建内部汇合值，在各分支入口赋值，让公共块使用这些值。只建立本函数内部的公共块，不引入新的函数调用。现有临时值重命名、活跃性和候选分配继续负责寄存器选择。

以 p051 作为首个通用模式实例，随后看 p095 和 USB 函数；不按函数名或 SDK 选择优化。公共尾部内的 volatile 读写仍按原路径顺序执行，不把访问提前到选择条件之前。

## 实施顺序与成果口径

1. **多路循环游标＋区域内 CODE 字节读取**：首先改善循环里的重复工作，同时观察体积和计时。
2. **带常量参数的 MIR 尾部共享**：首先处理相同终点的同形尾部，计算新增跳转/运输后的完整收益。

每项先用独立夹具与最相关的完整工程确认可获益，再扩大到同一配置的 75 项。已确认没有收益的 [循环活跃区间拆分](LOOP-LIVE-RANGE.md) 和全局字节读取策略不作为本轮原型基础。

本轮没有新增达标项或运行时间结果；片段编码已测，编译器实施与实板验证尚未进行。
