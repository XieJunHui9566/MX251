# STC-Link1D 可行性与首轮证据

日期：2026-11-09（Asia/Shanghai）。本工作优先恢复 MX251 的实板下载通道，不修改 SDK 来规避编译器不足。

## 结论

独立脚本方案可行：新下载器仍使用系统 HID、65 字节报告和旧桥相同的 64 字节程序分块。不需要新装 USB 驱动，不需要重写整个 ISP 协议。仅改 USB PID 不足以适配，新旧身份、状态布局和会话收尾确有差异。

当前交付为实验脚本，已完成一次脚本自身实烧，59 个代码块和配置写入均收到应答；用户确认 OLED 显示正常、与官方烧录后相同。下载与显示验证不是完整应用功能验收，也不是 MX251 相对 Keil 的性能验收。

- 官方应用：AiCube-ISP v6.97C，EXE SHA-256 `d857b147f2f4e527c5566a2dd40e63f875c94f4e344fa5ce800ab13a770db420`。
- 用户在 08:37:28–08:37:34 操作一次下载；本地官方日志 `ISPRESULT=0`，型号 AI8051U-34K64。
- Windows 描述为 STC-USB-Link1D，`34BF:1005`，HID MI_00；同时枚举两个 CDC 串口。本次下载全部经过 HID，没有观测到串口传输。
- 被动观察官方进程的 Win32 I/O；未主动发送设备报文、未修改官方 API 返回值。时间戳是主机 API 时间，不能作为 MCU 执行时间或 UART 位时序。
- 197 次发送、67 次接收，均为 65 字节；无记录序号缺口、采集错误或未完成操作。结束后已脱离官方进程。
- 官方下载 HEX 映像跨度为 3,772 字节，实际记录数据为 3,765 字节，地址空洞填 `FF`；59 个 64 字节块传输 3,776 字节，末尾额外填充 4 字节。抓包中全部程序字节与 HEX 一致。
- 59 个写块均得到 `02 54`，配置得到 `04 54`；没有 Flash 回读证据。

原始抓包和用户固件保存在本机独立证据目录，不提交公开仓库。可公开的文件指纹、数量和证据边界见 [stc-link1d-evidence.json](stc-link1d-evidence.json)。

## 已观察差异

| 项目 | 旧 AI8H2K12G 桥（既有实现） | 本次 STC-Link1D |
| --- | --- | --- |
| USB PID | FF0F | 1005 |
| 桥身份长度 | 19 | 26 |
| 桥身份前缀 | 51 01 04 FF | 51 01 19 FF |
| 目标状态长度 | 54 | 52 |
| BSL 原始字段 17/18/22 | 74 55 11 | 74 55 0B |
| 状态选项字节 8 | 2F（旧白名单） | AF |
| 配置包字节 44 | FC | FE |
| 结束控制 | 含 0D 01 | 本次没有 0D 01 |
| 关闭后重新打开 HID | 旧流程未采用 | 另发一份固定 65 字节控制报告，无观测应答 |

保持共同机制：`5A` 请求／`A5` 应答、报告字节和模 256 为零；`44` 按 56+13 分片缓冲一个 69 字节写块，`45` 提交并等待 `02 54`。地址仍为 FF0000 页内偏移。IRC 先测四个频段端点，再测目标邻域，使用当次结果生成配置，不能复用这块板的校准常量。

结束后的固定控制报告不符合普通载荷长度布局，代码将其单独保留，不猜测未确认字段含义。不把本次 52 字节状态的版本字段解释推广至其他芯片或 BSL。

## 实现与验证成本

选择 Python 标准库 + Windows 系统 HID；传输层与协议状态机分离。公开源码不包含 AiCube 二进制、Frida、用户固件或原始设备身份。

一轮完整离线回放已核对脚本生成的所有 197 个发送报告与官方记录一致，67 个接收报告全部消费。10 个针对失败路径及 HEX 的单元检查通过，包括错误身份、未知选项、校准失败、坏校验、块超时、坏块 ACK、坏配置 ACK、配置单独写入、地址越界和重叠。Windows 描述符枚举及官方进程互斥检查另外只读核验。

用户授权操作硬件后，使用实现提交 `101fe6d537b6070dc559275b61daa3ed2287242e` 对同一 HEX 实烧一次，08:47:34–08:47:40 完成。197 个发送报告、67 个应答，59 个写块及配置全部确认，发送运行与会话收尾控制。本次动态校准为 40,029,600 Hz，误差 0.074%；没有复用抓包中的校准值。退出码 0，无自动重试。
