# 符号数组地址与动态下标的调用效果

2026-11-13，实现 `d01b11e`，分支 `codex/symbolic-address-effects`。

本轮实际净收益 **9 B**：p136 从 4741 降到 **4732 B**，Keil 为 4128 B，比值 **114.63%**，到 110% 尚差 **192 B**。p045、p049、p071、p091、p122 均保持前版体积。没有新增达线项目。

## 通用实现

编译器在实际 XDATA 分配处输出对象空间与大小，绝对地址对象不产生此记录。构建侧结合 XSEG 分配、导出定义唯一性，以及本次链接使用的 XRAM 窗口，得到符号地址上下界；跨文件引用使用唯一的实际定义。没有绑定窗口、没有分配记录或定义重复时，不生成这类地址信息。

CFG 分析原先每字节只能保存“常量或未知”，现在能保留字节区间，并跟随寄存器拷贝、扩展、加减、掩码与物理字节重叠。动态下标产生进位后仍可证明最终写地址不会触及寄存器区，因此 callee 的 GPR 写集合不必变成全未知。改变的循环汇合值仍放宽为未知；调用、指针覆写和可能回绕进核心地址的路径不保留此前地址事实。

这里传递的是地址范围，并不要求访问地址是某个精确常量；也不把合法数组下标当作未经检查的前提。实际窗口来自正常构建的链接参数，不使用工程名、数组名或 SDK 内容特判。IR 算法和 SDK C 文件未改。

## 可行性结果与范围

对上一统一版本 40 项、63 个 `unknown-indirect-write` 函数进行只读估计，3 个可恢复为已知写集合：p071 的 `TestXRAM`、p091 的 `scsi_read_capacity10`、p136 的 `Alaw_encode`。估计读取的是旧版实际 XSEG 分配；真正编译时使用新增的对象记录。

三项完整复编后，只有 p136 形成净体积收益。`I2S_ISR` 保存分析现在识别三个调用，保存记录显示删除 8 B，最终整个工程净减 9 B。p071、p091 的摘要精确了，但没有可进一步消除的保存开销。另复编 p045、p049、p122，结果相同。这说明此路线目前的可兑现收益较小，不据 40/63 的候选数量推算收益，也不继续为该机制扩展全量重复验证。
