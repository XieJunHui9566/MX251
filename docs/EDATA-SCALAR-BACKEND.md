# EDATA 标量进入原生宽后端

后续 [整数格式化优化](INTEGER-FORMAT-DIVMOD.md) 已将 p083 从 1969 B 降至 1809 B，并将 p115 推入 120% 线；下文保留本阶段对照结果。

2026-11-14，分支 `codex/edata-scalar-backend`。编译器提交 `6fd6cb4`，函数裁剪接入提交 `31c16a7`。开发包位于 `E:/STVAPP/MX251-baseline/development/edata-scalars/core-next`，本轮没有替换冻结基线。

EDATA 整数和 float 值传递现在使用独立的内存节点，普通 16/32 位对象使用原生宽 MOV；volatile 仍逐字节读写。支持跨文件符号、绝对地址、ABI2/ABI4 实参，以及读取后经别名或函数修改再读取。整数截断保留旧后端的低位访问范围，SEND 和 IPUSH 保留各自的字节顺序。

新增汇编操作数 `e:(symbol+offset)`，明确指定 16 位线性地址，避免 extern 被按 direct8 编码。成本计算同步接入；函数裁剪器只在 MOV 操作数位置识别该前缀，仍追踪其中的真实符号，也仍追踪名为 `e` 的普通函数。编译器与新汇编器须配套使用。器件内存窗口、栈布局、C 指针 ABI 均沿用现有定义。

实现依据存储空间和类型决定，不含工程名称或 SDK 条件。DATA/SFR 的原路径保留。

## 验证

- `check-edata-scalars.py`：small/speed、large/size 各 21 个函数进入宽后端；9 类 volatile 字节序列与父版本相同，包含截断和两操作数读取。测试对象 CSEG 从 1808 B 降至 734 B。
- DATA 回归：原有参数对象测试在三种配置下均为 463 B；volatile 与 SFR 指令保持一致。
- `check-typed-cost.py`：新操作数的预测字节数与实际汇编一致；10 个既有汇编单元用新旧汇编器生成完全相同的 REL。
- `check-vector-function-gc.ps1`：14 项通过，含 EDATA 操作数与名为 `e` 的真实函数。
- 通用实板：128 组独立 Python 参考结果全部通过，覆盖 8/16/32 位、符号数、float 位模式、跨文件 ABI2/ABI4、volatile 全局对象、绝对地址和指针别名。测试固件 3713 → 2519 B；两组累计中位计时分别为 7775.5 → 5873、10016 → 4328，减少 24.47% 和 56.79%。这是该测试程序与父版本的板上对比，不代表全工程相对 Keil 的耗时结论。
- p083 六项原始算术及格式化输出也已上板核对。测试副本将 UART 时钟设为下载器的 40 MHz，并循环原来的六项计算，在下载完成后打开串口采集；未改变运算和格式串。该测试固件为 1979 B，随后函数裁剪接入移除 10 B 死函数得到对照产物 1969 B。

最初在下载前打开串口的单次采集不能可靠解码，相关原始记录保留于证据目录；成功结果来自下载后打开串口的重复采集。没有将这些未解码记录算作算术失败或通过。
