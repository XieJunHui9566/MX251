## 原因与修改

1. **同宽、不同符号的取负。** p135 的前端复制传播把 `long value = unsigned_result; value = -value;` 合并成有符号结果对无符号临时值取负。两者都是 32 位，既有 `0-x` 发射器已经能表达运算，导入器却要求符号相同。本轮移除这一限制，保留宽度、浮点及指针检查；整型提升仍由显式转换表达。
2. **内部形成的 IDATA 地址。** 将已有 DATA 对象来源和字节地址索引扩展到 IDATA。IDATA 的固定偏移也走间接访问，避免把上半区 RAM 当成直接地址 SFR。动态下标、地址快照、volatile 顺序和近地址转 generic 共用已有实现；运行期近指针形参、指针对象仍沿用旧后端。
3. **完整后端比较的编码计数。** 接上已有的 EDATA 符号索引解析，并补齐 `MUL AB`、`MOV A,@Ri` 与 `MOV @Ri,A` 的 Source 模式长度。此前 p135 候选虽明显更小，未知计数仍阻止 ISR 选择。本轮没有更改选择条件：ISR 仍要求完整体积严格更小、静态指令数不增加且两边成本已知。新环境变量 `MX251_BACKEND_COST_TRACE` 可打印未知成本的具体指令。

变更不按器件、SDK 名称或函数名选择。172 个含中断工程的 233 个 C 翻译单元重编译全部成功，23 个翻译单元的对象发生变化；对对应 23 个工程完成了全链接。g062、g063 的对象变化被后续链接处理抵消，最终镜像不变。新的 ISR 选择还覆盖 p105、p115 的 UART 中断。

## 验证

- `check-narrow-negate-encoding.py`：40 种指令形式的估算长度与实际汇编字节一致。
- `check-idata-negate.py`：small/large × speed/size，20 个编译单元，覆盖 IDATA 的固定/动态、1/2/4 字节和 volatile 访问，同宽取负及 8 位整型提升，两种 ISR 入口。
- `check-data-index.py`：四组 DATA 回归通过。原脚本中“支持导入必定最终选择 wide”的旧断言与上轮编译器行为已不一致，本轮改为检查候选确实生成，并允许完整成本比较选择更小的旧后端。
- 实物：STC-Link1D 自动定位至 COM13，**128 个组合、251 帧全部通过**。测试数组实际位于 IDATA `0x6d..0xec`，涵盖上半区 RAM；Python 独立计算预期结果，覆盖 ABI2/ABI4 的 16/32 位异号取负、零与最大正值，以及四个被打断寄存器组、GPR、PSW/PSW1、DPX、SPX、局部帧和未知汇编被调函数。
- 两个器件 profile、编译器副本与源码清单哈希一致。没有重新烧回旧固件。
