## 共性改动

修改位于 MX251 构建链的启动运行库生成阶段，依据实际链接区段、归档成员及 C 初始化代码决定发射内容；没有改 SDK 源码，也没有按工程 ID 或业务函数名称特判。编译驱动与上一版相同，变化由开发核心中的构建脚本和启动约定标识。

- 空 XINIT/XISEG、PSEG、XSEG 不再生成用于重现临时寄存器状态的指令。无参 C 入口保证对象初值、SPX 和目标中断状态；DPX、通用寄存器和算术标志不作为入口参数。
- 非空 PSEG/XSEG 只生成实际需要的清零循环。保留 24 位地址和计数；空区的循环及已知非空区的零长度检查不再发射。非空 XINIT 仍使用原复制实现。
- 已选中的默认启动钩子只返回 0，因此删除其启动调用和分支。若应用仍调用或引用这个钩子，保留库函数；用户自定义钩子继续使用原启动流程。
- 普通 C 全局初值、EDATA 初始化和只有数据定义的翻译单元也可以使用该路径。原始汇编初始化与用户归档继续沿用已有处理。
- 保留 DATA/IDATA 清零、目标的中断屏蔽、SPX 设置、向量及 main 返回后的行为。

Keil 安装中的 `LIB/START251.A51` 使用链接长度条件控制初始化段，本轮借鉴这一划分方式。MX251 仍实现自己的对象初始化和调用约定，没有复制 Keil 机器码。典型空外部区工程相对父版减少 52 B（36 B 临时状态装载、12 B 默认钩子调用及分支、4 B 默认钩子）；已有非空 XSEG 的工程通常减少 77 B。原来未获得空 CRT 裁剪的工程收益可更大。

## 验证

AI8051U-34K64、40 MHz，STC-Link1D 自动发现 COM13。三种固件分别覆盖 small 混合存储、large 混合存储和空外部初始化区；每种先用 128 个轮次的非零图案覆盖存储，再重入 C 启动入口并读取结果，合计 **384 个用例通过**。混合存储检查 DATA、IDATA、bit、EDATA、XDATA 清零，常量/部分数组/指针初值，以及每次重入后的栈和函数调用。绝对地址的未初始化 cookie 位于清零区外，仅用于记录启动轮次。

串口帧为复用格式，其中计时字段固定为 0；本轮只测启动正确性，没有把这些字段解释为执行耗时。原始 UART、下载日志及固件指纹在证据文件中。实板使用 core-02；最终 core-03 的两份启动实现文件与已测版本正文完全相同，仅规范了改动行的换行符，驱动和库二进制也沿用同一父版。

另有 6 类、8 次构建检查：STC32G small/large、PSEG 与 XSEG 均非空、应用显式调用默认钩子，以及自定义钩子返回 0/1。后两种分别与父版完整 HEX 相同。初次试编的统计将默认钩子的 8 B 寄存器区误计入代码体积，导致候选未被采用；已改为只统计代码区，随后试编与本次全量运行均采用修正版本。
