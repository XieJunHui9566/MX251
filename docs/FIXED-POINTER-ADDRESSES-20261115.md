## 根因和实现

MCS251 的远数据指针 `FPOINTER` 和通用数据指针 `GPOINTER` 都携带 24 位线性地址，宽后端用四字节寄存器保存并补零。原固定对象地址分析要求来源、结果的指针种类完全相同，因此 `&object → 通用指针 → 别名/偏移` 会丢失已经证明的对象来源。

`bits_messy` 中几个指针实际都指向同一个 volatile 位域对象。丢失来源后，新后端长时间保留多个四字节地址，增加调用保存和字节临时值的栈搬运。简洁写法没有经过同样的转换，已经能够使用 EDATA 直接访问。

本次允许已知对象来源通过这两种数据指针之间的转换。传播仍要求单一定义及支配关系，偏移必须落在已知栈对象或 EDATA 对象中；最终仍由完整函数候选比较决定是否采用。类型、地址位数、内存事务宽度和顺序保持原有实现。运行期未知指针、整数截断和 CODE 来源没有获得新的固定对象推断。

生产代码改动集中于 `wide_fixed_address_value` 和 `wide_fixed_object_addresses`。没有器件名、工程名、函数名或 SDK 特判，没有扩大入口能力或改 SDK 算法。

优化后 `bits_messy` 和 `bits_clean` 均为 324 B，实板每轮工作负载耗时相同，消除了这两种语义等价写法之间的主要落差。它们与 Keil 的剩余差距还包括字节移位、掩码、位测试以及算术调用的处理。

## 验证

- 新增 `fixed-pointer-addresses.c` 和 `check-fixed-pointer-addresses.py`：small/large × size/speed × ABI2/ABI4，共 8 组。覆盖远/通用指针往返转换、固定正负偏移、栈对象；普通参数指针、不同对象的分支合流、volatile 指针本体、CODE 来源、截断整数地址五类路径的指令保持相同。检查实际发射的 volatile 字节事务为写 offset 1、读 offset 1、读 offset 3。
- 编译测试比较忽略旧后端一次性输出的 `ar0..ar7` 汇编寄存器别名声明；前面的函数改选新后端时，这些声明会挪到后面的旧后端函数，机器指令不变。
- 既有用户压力测试 **63/63 编译单元通过**。`bits`、`fields`、`ring` 的 27 个 REL 缩小，其余 36 个 REL 与上一版逐字节一致。三种目标描述的纯 C REL 继续一致；GCC 参考结果覆盖 3,072 次求值、1,536 组等价写法比较。
- 同源完整用户固件在 AI8051U 上取得 **3,705 帧，覆盖 832 个结果**，每项至少四次采样，零结果错误、零计时溢出。768 项为 12 类工作负载 × 64 输入，另有 64 项空控制。
- 复用同板、同源、同设置的 Keil 固件及原始采样。Timer0 测量区域包含分发、工作负载和结果搬运，不含 UART；按烧录时测得时钟归一化。空控制不扣除，不计入达线数量。
- 官方代表工程 `g104`（3,643 B）和 `g133`（8,591 B）重新构建成功，最终 HEX 与已有官方矩阵结果完全相同；不更新全量 97 工程的达线统计。

测试使用正常候选封装入口，保留上一轮 1024/2048 容量及通用优化。原主工作区的三项用户改动未触碰。板上保留本次测试固件。
