# 固定中断向量参与函数引用分析

基于 `6f311dd`，沿用 `codex/float-format-edata` 分支。改动位于 MX251 正常构建链；SDK 源码、编译器可执行文件及数学运行库二进制均未改变。开发包：`E:/STVAPP/MX251-baseline/development/vector-function-gc/core`。

## 差距归因

p077、p079 的原始汇编使用绝对地址跳到编译器的中断向量。函数 GC 原先把它们列为 `ABSOLUTE_CONTROL_TARGET`，整图保留全部函数。Keil 已经删除的触摸校准、触摸采样等代码及其浮点运行库因此继续进入 MX251 映像。

正常构建入口现在把已有中断选择计划及实际 CODE 基址交给函数 GC；数字目标若正好是已登记 ISR 的向量入口，就建立到对应单元/ISR 的引用。向量地址按 CODE 基址、槽号计算，没有工程名或固定地址特判。原汇编文本保持不变；最终向量表仍由既有链接检查核对。

未登记目标、向量中间地址及尚待归档抽取的向量继续沿用原处理。本轮不增加任意机器地址解析。

“其余 CSEG”包含运行库、生成的格式化实现及未归属函数的代码/表，不能全部解释为浮点库。函数数值统计实际指令字节；常量另列。

p077 删除 18 个函数，原函数指令共 5903 B。随后既有链接和优化流程也减少了辅助库、启动和调用开销。

p079 删除 20 个函数，原函数指令共 6107 B。随后既有链接和优化流程也减少了辅助库、启动和调用开销。

两项的未使用浮点运算依赖退出链接，说明这部分体积差距首先来自函数保留范围。常量占用没有变化。p079 的标准运行库构建还由既有 AUTO 流程选中了更小的局部寄存器 ABI 候选。

## 验证

- 9 项函数 GC 检查通过：有效向量、十进制地址、不同 CODE 基址、ISR 辅助调用保留、无用函数删除，以及未解析目标的原处理。
- 5 个工程 × 2 种运行库，共 10 次正常构建完成；p077/p079 最终向量表核对通过。
- AI8051U 实板 Timer3/Timer4 经 `0xff009b/0xff00a3 → 0xff006b/0xff0073 → ISR → RETI` 执行，128 组、550 帧正确。ISR 调用辅助函数，未使用浮点除法函数从映像中删除。
- 板测固件 SHA256：`ea37f78fa8998bcd3048f17ae8e912c23b39f2ff3a596f5c2f21d652b2da727f`。原始串口和烧录记录保存在开发目录，仓库只记录结果与证据哈希。
- 本轮收益是体积；未新增 Keil 整工程耗时对照，原 75 项冻结统计保持原记录。

初次软件调用模拟中断的夹具未收到串口帧，未用于通过结论；最终采用硬件定时器产生真实中断帧，复现脚本只生成这份通过的夹具。
