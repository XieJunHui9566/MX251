# 软件浮点打印与默认 EDATA 布局

本轮从 `ccea05d` 开始，分支 `codex/float-format-edata`。改动属于 MX251 编译器、运行库生成器和正常构建入口；官方 SDK 源文件未修改。开发包位于 `E:/STVAPP/MX251-baseline/development/float-format-edata/core`，冻结基线保持原样。

## 软件浮点与格式化输出

AI8051U 的正常目标配置现在支持 `runtime: "native-math"`，使用已存在的普通 C ABI 及软件浮点库。原来的 `standard` 配置仍可用；大型 LCD 工程不一定在切换数学库后缩小，因此没有全局强制切换。

固定 CODE 格式串的 `printf`、`sprintf` 新增 `%f`、`%F`，支持 0～9 位小数、缺省 6 位、最多 255 字段宽度和零填充，可与已有整数、字符转换混用。生成器复用原有调用对象与变参槽分析，实际消费目标的 4 字节 double 槽。动态格式、其他转换或更大精度继续使用完整运行库。候选链接只有在完整映像更小时才采用。

新转换内核把 binary32 尾数乘以十进制精度后作精确的二进制缩放，最后按最近值、遇中间值取偶数舍入。只用整数运算，覆盖整个有限 float 范围、非正规数、正负零及 NaN/Inf；不使用额外浮点运算或 64 位除法辅助。十进制临时数组为 48 字节，自动存储，可重入。格式化与舍入语义参考 [WG14 C23 草案的 fprintf 条款](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)。

运行库归档仍按目标 profile 的哈希绑定。格式化替换现可与普通 `native-int`、`native-math` 共同使用；数学库成员本身没有被格式化生成器改写。

## 默认 EDATA

编译器新增 `--mcs251-default-edata`，正常工程的 schema 2 配置可写：

```json
{
  "model": "small",
  "runtime": "native-math",
  "defaultDataSpace": "edata"
}
```

这三项填入已有 `mx251.json`；`defaultDataSpace` 与数学运行库选择相互独立，也可用于 `standard`。该选项将未指定空间的全局和静态对象放入 EDATA，自动局部变量仍在栈上；显式 `__data`、`__xdata`、`__edata`、位变量及绝对地址保持各自含义。要求 small、stack-auto；不填写该选项时沿用原有布局。

沿用当前目标内存合同：EDATA 从 `0x100` 分配，AI8051U 当前栈从 `0x400` 开始，因此本配置下栈前可分配 768 字节。绝对对象保留及溢出诊断由既有链接器处理。每个编译单元的连续 EDATA 对象共用一段清零循环，先清零再执行显式初始化；带初始化的绝对对象仍单独处理。

同时修复了局部静态初始化的函数元数据：GSINIT 片段不再借用所属函数的身份重复声明函数体。该问题会阻止格式化替换和其他依赖函数边界的分析。

函数 GC 删除单元内全部函数后，可能仍留下变量和常量字节初始化。格式化分析现在识别这种生成结果，不再要求该单元必须有函数体。初始化中的调用、跳转、可执行字节和其他指令仍使用完整格式化运行库。p076 的触摸模块触发了这项通用修复。

## 验证与结果

数值内核通过 80,720 组宿主对照，覆盖全部 256 种指数、两种符号、尾数边界、随机位型和 0～9 位精度。默认 EDATA 12 项编译/链接检查、原显式 EDATA 29 项检查及既有变参格式检查通过。

AI8051U 实板测试自动发现 STC-Link1D 后下载。正常构建入口生成的固件通过 128 组、543 帧，包含混合整数/浮点变参、printf/sprintf、跨文件 EDATA 访问、部分初始化、初始化指针和局部静态对象。启动前先写入非零数据，验证真正执行了清零。显式 DATA/XDATA/EDATA 同时参与测试。
