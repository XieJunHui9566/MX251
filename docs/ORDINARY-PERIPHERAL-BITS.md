# 普通函数外设位优化

2026-11-10 普通函数外设位优化：统一核心 **75/75 成功，64 项体积 ≤Keil 120%，其中 50 项 ≤110%**；26 项缩小、49 项相同、0 项变大，净减少 **415 B**。合计 204986 / 192051 B（106.74%）。独立实板前后各 128 项通过，组合用例耗时减少 38.31%；完整工程运行时间未测。

分支 `codex/ordinary-peripheral-bits`，父版 `eee789a`，最终编译器实现提交 `f5f1c52`，最终实板夹具提交 `a6dd527`。全部工程采用同一编译器、配置及原有 SDK 源输入；修改集中在 MX251 后端与目标能力，无工程 ID、SDK 名称或函数名特判。逐项证据见 [ordinary-peripheral-bits-evidence.json](ordinary-peripheral-bits-evidence.json)。

## 通用能力

- 有序汇编与机器指令层共用 CLR/SETB/CPL 数字 byte.bit 解析。外设写及先后顺序保留，GPR 副本可跨已知位操作复用；映射控制仍保留自己的状态边界。
- 普通旧后端的已知有序位操作也接入机器优化。PSW 的 PUSH/POP 保留局部效果边界，bank 修改未放入该路径。
- AI8051U 目标能力补充 S2CON、IE2、SPSTAT、SPCTL。`0xaf.7` 指 IE2.EUSB；经典 sbit 地址 0xaf 则是 EA，两者不混用。
- 对含有序位操作的完整函数，比较包含原生寄存器参数调用、switch 跳转表的两套实现。补全跳转表间接 JMP、CPL 位指令及 b0～b7 内部位临时量的成本。
- 有序 I/O 函数按完整体积选择后端，不再为少一条静态指令而选用更大的地址/参数准备代码。静态指令数不是执行时间；本轮未声称每个完整工程都达到运行时间目标。

## 试编译决定了哪些改动

初版开放位能力后，p095 的 `_uart_polling` 从 534 B 增至 736 B。原因先后为原生调用、switch 被排除出成本比较，以及 `mov b0,c` 缺少成本。修正后保留 534 B 的旧实现。

USB 初始化原先为少一条静态指令，选了更大 12 B 的宽实现。现在选用完成机器优化后的旧实现，比父版减少 2 B。p096 的 `_usb_class_in` 则选宽实现，从 566 B 降至 465 B。p136 的 `_SPI_Config` 保留 295 B，不能把“获准优化”直接当作收益。

core-01～core-03 为试验版本；推荐 core-04。首轮和中间试编译结果、失败诊断仍保留在研究目录。

## 验证与实板计时

- 机器层：189 组程序、12096 次执行，包含位操作顺序、重复写保留与寄存器副本复用。
- 编译器：small/large × speed/size，覆盖访问顺序、能力开关、核心状态/未知指令回退、原生调用、跳转表、内部位临时量。

- 最终实板源输入相同，Python 独立计算预期；64 个组合输入和 64 个对照输入均通过。组合输入含 IE2/UART2/SPI 位读回、volatile 对象、活跃标量、原生调用与跳转表；`bits_choose` 选旧后端、`bits_work` 选宽后端。
