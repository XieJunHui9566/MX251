## 实现

ABI4 现在接纳 24 位 CODE 对象指针作为参数和返回值。前两个参数沿用 DR4/DR12 槽，返回值沿用 DR4；三字节物理指针对应 R5–R7/R13–R15，MIR 的第四字节补零。后续栈参数保持三字节，参数取址复用相同物理槽。指针的 CODE 类型一路传递到读取操作。

普通 C 函数可显式使用 `__reentrant __sdcccall(4)`，并启用 `--mcs251-native-abi`；宽后端使用 `--mcs251-wide-ordinary` 或 `--mcs251-wide-backend`。ABI3 仍保持原类型集合。普通 ABI2 与公开 printf/sprintf 的声明和调用约定保持兼容。

格式化生成器对同一格式需求编译三个完整内部调用方案，以汇编对象 CODE 区总字节数选择：

- `abi2`：格式循环、转换函数均用普通调用。
- `body4`：格式循环用 ABI4，数字与浮点转换保留 ABI2。
- `abi4`：格式循环、数字与浮点转换均用 ABI4。

公共变参入口始终使用 ABI2，所有内部调用者与被调用者一起生成。每个候选的 C、ASM、REL 保存在构建目录 `format-abi2`、`format-body4`、`format-abi4`，选择结果写入 `format-runtime.json`，选中命令仍标记为 `format-runtime`。没有工程或 SDK 名称条件。比较的是对象体积，运行时间由下面的实板测试记录；本轮没有建立循环时间成本模型。

## 下一处值得做

ABI4 仍没有参与普通 ABI2 的完整后端成本选择。16 位无符号取负会让部分转换函数整函数回退旧后端，这也是纯 ABI4 方案在 16 位整数用例中明显变大的原因。下一轮应统一这层后端选择，而不是继续只围绕 p083 剩余 5 B 做局部修改。
