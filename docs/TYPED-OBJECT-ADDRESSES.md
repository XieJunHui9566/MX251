# 对象与地址原型：收益不足，停止扩展

2026-11-09，承接 [大收益方向筛选](HIGH-YIELD-STUDY.md)。原型已经实现并完成两个代表工程的完整构建。**p087 减少 1 B，p091 减少 14 B，不符合本轮寻找大收益的目的。** 生产编译器已恢复父版，原型以补丁保存，避免以后重复试验。

## 实现范围

没有修改 SDK 输入或 ABI。编译器原型包含四项变化：

1. DATA 对象布局接受物理三字节指针成员；相邻整数成员不再因它被拒绝。
2. 指针字段沿用四字节 MIR 值，但只读写三个实际字节，寄存器补位不写入相邻字段。
3. 将直接对象地址及常量偏移保留到存储节点，直接生成三个符号重定位字节，消除中间宽地址值。仅覆盖单用转换后直接存入字段的情况，没有全局放开 CODE/数据指针转换。
4. 普通 DATA 整数成员可直接使用字/双字访问；volatile 仍沿用已有事务规则，立即数成员写入保留逐字节形式。

原型补丁：[typed-object-addresses.patch](../tools/research/typed-object-addresses.patch)。小型编译输入：[typed-object-addresses.c](../tools/research/typed-object-addresses.c)。这些文件是研究材料，不参与正常编译器构建。

## 完整镜像结果

父版编译器来自 `964d31b`，本轮分支从研究提交 `c145a9d` 开始，使用相同 small/speed 配置和标准运行库。两个工程全部输入哈希与父版 receipt 一致。结果取最终 HEX，使用已有分析器核对最终 ASM/RST 指令。

| 工程 | 父版 / B | 原型 / B | 变化 / B |
| --- | ---: | ---: | ---: |
| p087 USB CDC | 4769 | 4768 | −1 |
| p091 USB MSC | 6312 | 6298 | −14 |

只加入布局与三字节读写的中间版，p087 曾增加 72 B。完成直接符号存储及整数成员宽访问后，回到上表结果。这是一次原型的分阶段实现，不是多套优化收益的累加。

## 为什么没有形成大收益

新增导入确实生效：p087 有 8 个、p091 有 7 个原来拒绝的函数进入宽后端。包括 `usb_get_status`、`usb_get_descriptor`、`usb_ctrl_in/out` 及配置/接口查询。

但旧后端原本就能高效生成部分直接字段访问，新后端的控制流和指针计算抵消了局部减少量：

| 函数 | p087 父版 → 原型 / B | p091 父版 → 原型 / B |
| --- | ---: | ---: |
| usb_get_status | 261 → 233 | 255 → 224 |
| usb_get_descriptor | 167 → 156 | 232 → 222 |
| usb_ctrl_in | 153 → 163 | 153 → 163 |
| usb_ctrl_out | 134 → 151 | 129 → 146 |
| usb_get_configuration | 81 → 85 | 81 → 85 |
| usb_get_interface | 56 → 60 | 56 → 60 |

其他函数的分配、调用保存与成员访问也有变化，完整列表保存在 [typed-object-addresses-evidence.json](typed-object-addresses-evidence.json)。不能只相加变小的函数而忽略整镜像结果。

这次结果修正了上一轮判断：**整函数回退的覆盖率描述能力边界，不能代表优化空间。** 该原型证实了对象表示可扩展，没有证实它是大收益来源。也不能凭这个局部实验否定整个编译器架构。

后续筛选应从同条件 Keil 与 MX251 的具体函数、实际指令差额出发，先区分语义操作数量、地址计算、控制流和调用运输成本；不再只按回退函数数或新增宽后端覆盖率选择重构。
