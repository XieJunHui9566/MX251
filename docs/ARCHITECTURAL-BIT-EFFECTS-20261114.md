# 通用 SFR 位操作准入（2026-11-14）

基于 `bcd3d95`；实现与测试提交 `1a6dae0`。编译器 SHA-256：`4ca8c6b78f13ca6e3c60aebebbd71dfefc912b8e83a965043abd524287b14ea6`。

## 原因与改动

父版 97 个可构建官方工程中，124 处函数回退首先卡在 `ordered-asm-bit-not-capable`。新后端已经能发射这些指令，机器指令效果与中断保存分析也能识别普通 SFR 位操作，但导入仍依赖两个器件各自维护的逐地址白名单。

新增 `--mcs251-ordered-asm-bits peripheral-v1` 架构契约：按现有核心状态分类，统一接入普通 SFR 的数字 SETB/CLR/CPL，继续使用完整访存和顺序屏障。明确的 `NN:MM,...` 数字掩码保留原来的限定范围与编译结果。

架构描述设置统一契约，AI8051U/STC32G 删除重复外设位表；设备层仍描述 SPH 布局和 EAXFR 等特殊映射作用。编译器没有器件名、SDK、工程名或函数名匹配。没有修改 SDK 源码、位操作时序或既有 ABI。

这个契约要求编译器存储、寄存器组与栈在普通外设操作后仍可访问。SP/DPTR 扩展、PSW、ACC/B、模式控制及已有映射位分类继续生效；特殊硬件改变这些条件时需要对应描述，不能把本次契约等同于任意未知器件的全部 SFR 资格。

## 独立验证

- ABI2/ABI4 × small/large × size/speed，8 种配置；SPH85 布局覆盖 920 个普通位、每组 116 个函数及 2760 条位操作。检查最终 SETB/CPL/CLR 数量、顺序和前后真实 volatile MOV 访问。
- 这些短函数每组 1 个选新后端、115 个经成本择优选旧后端；全部完成新后端候选构建，没有语义回退。准入不等于强制选新后端。
- SPH85/legacy 布局分别检查 106/114 个核心状态或低地址位案例，与父版旧后端 REL 相同。数字掩码接口的 REL 也与父版相同。
- 原有内存状态测试 24 组通过，7 项无效声明按原规则处理，关闭能力和排除项输出不变。
- 自造复杂 C 用例涉及位读回、长整数运算、栈变量、DATA/EDATA/XDATA 和跨函数调用。16 个函数全部选择新后端，ABI2/ABI4 各 512 项，AI8051U 实板合计 **1024/1024 PASS**，串口 COM13。
- 硬件用例使用 IP2/IP2H 优先级寄存器的已声明位，EA 保持关闭；地址依据与头文件哈希见 `register-evidence.json`。主机使用独立普通 C 位运算得到期望值。
- 原用户程序压力集 **63/63** 编译成功，三个目标描述纯 C 对象相同，且全部 63 个 REL 与父版逐字节相同；主机 3072 次求值、1536 对等价结果通过。

同源完整压力固件 **41694 → 15530 B**，减少 **26164 B（62.75%）**。复杂函数不再因一条外设位操作整体回退，因而能使用已有的通用运算、寻址和调用优化。这个降幅只属于该自造压力用例，不能外推到所有应用。

## 回退变化与后续

原 124 处位能力回退现在的分类：62 处选择新后端，62 处通过候选比较后选择旧后端，没有继续因位能力或新暴露的语义问题回退。统计单位是工程/编译单元/函数，跨工程复制的函数不去重。完整清单见 `admission-transitions.json`。

剩余首个回退原因：

- `ordered-asm-core-state-write`：10 处。
- `arithmetic-width-type-or-operand-contract`：7 处。
- `unsupported-volatile-dummy-read-operand`：4 处。

后续不需要继续补普通外设位白名单。应把剩余通用算术/volatile 读取缺口与已成功编译但代码较大的函数分开统计，再选下一项；特殊模式/映射控制仍按实际语义处理。`CPL` 多行块的链接不透明标记也是可审查方向，它与寄存器效果及内存屏障是不同问题，本轮未改链接元数据。
