# CODE 常量读取与地址生成优化

2026-11-10 CODE 常量读取与地址生成：统一核心 **75/75 成功，64 项体积 ≤Keil 120%，其中 49 项 ≤110%**；2 项缩小、73 项相同、0 项变大，减少 **168 B**。合计 205401 / 192051 B（106.95%）。独立实板前后各 128 项通过，CODE 组合用例耗时减少 5.81%；完整工程运行时间未测。

实现提交 `12a5ee1`、`6a479e0`，父版 `1c79975`，分支 `codex/native-code-loads`。所有源算法保持原样；改动是目标能力声明与 MX251 通用后端，不含 SDK 名称或工程 ID 判断。逐项证据见 [native-code-evidence.json](native-code-evidence.json)。

## 实现

- 新增 `--mcs251-flat-code-reads`，表示目标的 CODE 指针采用统一 24 位物理地址，支持奇地址原生字读取。AI8051U-34K64-32 的目标配置声明 `flat24-code-reads-v1`；构建器自动传递参数，并写入 receipt。没有该能力的目标继续使用原路径。
- 对非 volatile 的 16 位 CODE 读取发射一个 `MOV WR,@DR`；32 位读取发射两个字读取。MIR 中仍保留 CODE 类型和只读限制。输入地址与输出重叠时使用已有访存临时寄存器处理。
- CODE 指针加减的唯一使用者是同一直线片段中的字/长字读取时，将地址计算合入读取；继续使用原 24 位指针和有符号偏移语义。
- 窄无符号乘 2/4 使用一/两次加法，适用于普通算术和数组索引，保留原结果宽度的截断。
- volatile CODE 保留逐字节 MOVC 与完整 DPX 自增。字节常量表保留原有路径。

## 为什么没有全面替换字节 MOVC

第一版也使用原生字节读取，但这使 DisplayScan 等字节查表函数从紧凑的旧后端切换到宽后端：例如原 85 B 变为 102 B，静态指令数只从 41 降到 40。宽后端的完整地址构造抵消了单次读取的收益。最终版将新读取限定为 16/32 位，不修改全局后端选择策略。首轮完整 75 项中 10 项缩小、15 项增大、合计增大 148 B。core-01 与 trial-comparison.json 保留作研究证据，推荐 core-02。

## 验证

- CODE 编译检查：small/large × speed/size × 能力开关，共 8 组；覆盖 8/16/32 位、float 位运输、奇地址、递归与 volatile；10 组 CODE 写入、atomic 和 ABI4 边界检查通过。
- 现有字节乘法 4 组配置通过。旧字乘法脚本的“只接受 13 个函数、byteword 必须回退”断言已落后于父版：父版和候选均接受 14 个，其 small 模型生成对象 SHA-256 完全相同；该旧脚本不记作通过。
- 新建独立实板夹具：字节、字、长字、奇地址长字、跨 256 字节边界、volatile 字节读取、ABI2 CODE 指针及窄乘法。128 项包含 64 个 CODE 组合输入和 64 个未改动对照输入。Python 独立计算预期结果；新旧固件读取完全相同的源输入。

| 实板版本 | 固件/B | CODE 组合计时总和 | 对照计时总和 | 结果 |
| --- | ---: | ---: | ---: | --- |
| parent | 3643 | 41600 | 10115.0 | 128/128 |
| new | 3604 | 39184 | 10115.5 | 128/128 |

计时为 64 个输入各自多帧中位数之和；AI8051U 实验箱 40 MHz，Timer0 /12T。最终 CODE 组合用例减少 **5.81%**，固件减少 **39 B**。STC-Link1D 自动定位为 COM13，序列号 82941086。此结果与 Keil 整工程运行时间达线无关。
