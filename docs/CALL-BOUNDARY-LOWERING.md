# 普通尾调用、分派表直达与中断保存

2026-11-09，基于 `3af86ca`，开发分支 `codex/call-boundary-lowering`，实现提交 `54c3238`。这一批完成通用调用边界优化，三个 USB 完整工程减少 148 / 157 / 153 B；TFT 减少 6 B。SDK 源文件及构建选项与父版本相同，输入哈希和逐函数变化见 [证据](call-boundary-lowering-evidence.json)。

## 实现

- 宽后端把尾调用识别从“ABI4、紧邻显式 RETURN”扩展到兼容的普通 ABI2 调用、隐式 void 返回，以及经过 LABEL/GOTO 的共同返回出口。直接保留被调函数的物理返回值。仍需调用者清理的栈实参、仍可能被被调函数访问的局部对象/取址形参、返回转换和不同返回约定继续执行真实调用。
- 根据上述尾调用计算实际发射的可达节点。无参数、无帧的尾调用分支可以直接作为跳转表表项，删除只起中转作用的 case 块。共享出口仍按其他前驱保留；表项仍为固定 4 字节 EJMP，不改变原有索引范围及远地址计算。
- 普通 bank0、包含调用的 C ISR 使用八组 DR 保存完整 R0..R31。先保存 PSW1/PSW，再切换 bank0，退出时先恢复通用寄存器再恢复原 PSW，PSW1 最后恢复。保存字节总量与旧入口相同，C 局部对象栈偏移不变。独立寄存器组、naked、critical、内联汇编、xstack、debug 及排除 A/B 的入口继续使用原有生成路径。
- bank0 ISR 内的普通调用可使用既有被调函数实际写集合，省去不受影响的 R2..R7 保存。入口的异步现场保存独立保留。
- 完整构建会发现独立 ISR 翻译单元中的直接调用，并提供上述反馈；ISR 自身仍为未知普通调用效果、ABI 0，不会被当成可普通调用的保留寄存器函数。

没有按 SDK 函数名、工程 ID 或设备型号选择这些优化。公开 ABI 和运行库接口保持原有约定；这一批尚未实现静态局部变量覆盖分配或新的 callee-saved ABI。

## 完整工程结果

各项均开启已有函数共享、MachineIr、函数 GC 和调用反馈，使用 small/speed。TFT/MSC 保持已有 NativeIntegerRuntime，两个 CDC 保持标准运行库。双 CDC 的父版本在本轮用相同输入重建。

| 工程 | 父版本 / B | 本轮 / B | 减少 | 降幅 |
| --- | ---: | ---: | ---: | ---: |
| p080 TFT | 21473 | 21467 | 6 | 0.03% |
| p087 USB CDC | 4745 | 4597 | 148 | 3.12% |
| p091 USB MSC | 5928 | 5771 | 157 | 2.65% |
| p095 USB 双 CDC | 6595 | 6442 | 153 | 2.32% |

| 函数 | 父版本 / B | 本轮 / B | Keil 原厂基线 / B |
| --- | ---: | ---: | ---: |
| usb_req_std（三个 USB 工程） | 158 | 88 | 92（CDC/MSC） |
| usb_isr（CDC） | 255 | 179 | 132 |
| usb_isr（MSC） | 242 | 166 | 124 |
| usb_isr（双 CDC） | 298 | 222 | 本轮未重做对照 |

ISR 每个减少 76 B，其中入口/出口成组保存减少 48 B，已有调用写集合用于 ISR 再减少 28 B。函数局部收益与镜像总收益不能简单相加，其他函数的后端选择、调用效果和保存会随之变化；证据文件保留全部对应函数。

TFT 的主要差距没有被这批改动消除。上一轮审查中“局部存储、参数和跨调用寄存器应一起设计”的结论仍成立。本轮没有重跑全 SDK，也没有新增完整工程双 120%/110% 达标记录。

## 验证

- 新增尾调用编译/汇编检查：small/large、speed/size 四种组合，覆盖字节、word、dword、float 位模式、指针、入口栈参数、原生 ABI4、void 分派，以及必须保留真实调用的对象地址、栈实参、ABI 转换和返回后运算。
- 既有原生调用：small/large 各 33 个接受函数及一个既有回退通过。
- 既有普通调用：18 组配置/边界通过。原测试仍把第九参数当作超限，已按此前实现的 16 参数容量改为第十七参数；父版本第九参数对象本就通过，不能将陈旧断言当作本轮回退。
- switch 四组通过，包括 256 项表、嵌套分支、溢出、volatile 和调用；CY 返回值八组通过。
- 中断编译/汇编检查：64 项通过，覆盖 small/large、stack-auto 开关、speed/size、peep 开关和四类入口。
- 新增调用图检查确认 ISR 的调用能够参与反馈，同时 ISR 不导出普通调用约定。
- 四个完整工程均完成最终实际调用保存核对，源输入 SHA-256 和相关构建选项与各自父版本相同。

实板为 AI8051U-34K64，使用既有 40 MHz、UART1 P3.0/P3.1、115200 8N1 外壳。STC-Link1D 序列号 `82941086`，本轮自动找到 COM13。最终测试为 **128 个用例、252 帧全部通过**：64 个尾调用组合结果由独立 Python 定宽整数计算核对；64 个真实 Timer0 中断用例覆盖四种原寄存器组、R0..R31、PSW/PSW1、SPX 低字和栈内局部对象，还覆盖已知 C 被调函数与破坏全部通用寄存器的汇编被调函数混用。最终汇编确认实际删去了跨 `context_echo` 调用的 R6 保存，未知汇编调用保留原有保存。

首轮中断夹具曾因手写 `MOV DR,#imm32` 实际只装入 16 位而报错，原始串口保留。最终夹具改为两个 word 装载来预置完整 32 位；该问题不属于编译器生成结果。串口额外输出完整上下文，供定位差异。

本夹具复用了 Timer0 作为中断源，记录中的 tick 不作为相对 Keil 或父版本的性能成绩。最终固件保留在板上，没有恢复旧固件。
