# 相邻内存地址复用

2026-11-13，实现 `7b10e4d`，分支 `codex/relative-memory-address`。

统一 75 项：**75/75 体积 ≤Keil 120%、66/75 ≤110%**。2 项缩小、73 项不变、0 项增长，净减少 **26 B**。最终产物保留 7 处相对地址复用。

## 实现

同一指针的常量偏移访问，原来反复复制基址、相加、清除高八位。本轮在现有发射器中保存 `DR16 = (base + offset) mod 2^24`，下一次按偏移差递增或递减，保留每次 24 位规范化和原内存事务。

复用可穿过未改写基址、DR16 的普通计算和已知直接对象读取。实际发射指令的写寄存器集合决定何时结束复用；分支、调用、未知效果和内存状态变化也结束复用。读取结果若覆盖原基址，不再延续该地址。普通 LOAD/STORE 使用此路径；volatile、CODE、三字节指针对象和原生位移访问仍由各自路径生成。

沿用分配后的寄存器，不增加活跃虚拟值或栈槽，不修改 SDK。规则不依赖工程或函数名称。`MX251_RELATIVE_ADDRESS=0` 可恢复父版指令。

## 接续判断

这项配套优化已兑现此前 p136 的两段地址复用空间。收益较小，后续不再单独扩张这条规则；优先重新归因剩余九项的后端回退和 ISR 调用保存开销，再选择能明显缩小缺口的改动。

接续线索：当前 p045 `timer0` 的入口/出口保存指令占 40 B，冻结 Keil 列表为 20 B；`LVD_Routine` 仍保存全部八组 DR，且含 `JBC 0x87.5`。已有 ISR 分析器把 PCON 低六位归为未知核心状态。这里先记录实际断点，尚未证明可以删掉相应保存；应分清影响执行状态与实际改写 GPR 的效果。p049 的 `CMP_Isr` 也保留完整保存区，需沿实际调用链定位未取得效果摘要的原因。
