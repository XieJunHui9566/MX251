## 实现及选择依据

- 新增 `--mcs251-memory-state-bits NN:MM,...`：声明保留 GPR、标志、栈和编译器对象存储的映射位。导入现有有序 MIR 节点，并标记 `memory-state=1`；访存与调度屏障仍在原位置，寄存器中的普通值可以跨越它。
- AI8051U-34K64-32 目标 revision 4 声明 EAXFR（`ba:80`）。参数进入编译命令、构建身份和 receipt。普通位许可仍不能包含 EAXFR；未声明目标与 `OrderedAsm OFF` 保持原处理。
- 成功导入的有序汇编函数继续进入最终机器指令优化。数字位操作在该层形成局部边界，NOP 和状态写的次数、顺序保持不变。
- 这些函数同时参加双后端比较；字节后端体积更小且静态指令数不增加时，采用整个字节后端函数。补齐 JBC 和 Source 模式间接字节 MOV 的成本，并按实际汇编编码核对。循环的静态指令数是选择启发式，不宣称所有输入下的耗时上界。

只开放宽后端而不做成本选择的全量试验是 **27 项缩小、33 项变大、净增加 1304 B**。因此不能把准入函数数量当成收益；最终版本结合实际成本选择。试验记录保留在外部 `admission-only.json`。

原先因核心状态操作回退的 90 个函数，最终 42 个采用宽后端、21 个经比较采用字节后端、27 个仍受其他条件限制、0 个不再单独出现在最终镜像。详细归因见 `function-attribution.json`。

## 编译与实板

24 组检查覆盖 small/large × speed/size：状态位两侧的访问顺序、EXTRAM/寄存器组/栈写排除、混合汇编块整体处理、字节循环的成本选择。关闭能力后的 REL 及排除案例、被选字节循环均与父编译器相同；7 个无效能力声明被拒绝。另有 30 条指令成本与汇编器编码一致，已有整函数成本选择检查通过。

AI8051U-34K64、40 MHz、STC-Link1D 自动发现 COM13，最终固件 **128 个用例、646 帧通过**。夹具在 EAXFR 切换两侧执行 edata/xdata、volatile 局部栈、32 位活跃值、函数调用以及 XFR 读取；两组分别使用单条状态指令和与 NOP 混合的状态块。

相同夹具的镜像 **1999 → 1163 B**。两组总计中位 tick 分别为 27066 → 12896、27231 → 13064，耗时为父版的 **47.65% / 47.97%**。这是独立夹具相对上一版 MX251 的实测，不是全部 75 工程相对 Keil 的运行时间。

厂家手册第 13.1 节（印刷页 607，PDF 页 646）说明 EAXFR 控制独立 XFR 地址区；本轮据此结合实板核对。文档来自[厂家手册镜像](https://atta.szlcsc.com/upload/public/pdf/source/20250721/992B74DF6B5BF6F1D6B71F636228C6F2.pdf)，文件哈希已存入证据。EXTRAM 的对照用例在新旧编译器下都出现结果变化，因此没有纳入目标声明；这里没有把地址表说明直接当成所有访存指令的存储保证。
