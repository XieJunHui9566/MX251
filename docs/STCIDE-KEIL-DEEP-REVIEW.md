# Keil 与 STC-IDE：寻址、调用和全程序优化的进一步拆解

2026-11-09，分支 `codex/stcide-codegen-study`，研究基线 `c169c5b`。结论是优先推进**地址信息保留与统一寻址降低**：让对象、地址空间、偏移宽度和循环游标的信息进入代码生成，减少通用指针的重复转换与搬运。STC-IDE 提供了一条可参考的特化路线，Keil 则证明一般指针本身也能编译得很紧凑。当前证据不支持照搬 STC-IDE 的全部设计，也不支持重做已有低收益原型。

本轮实施了研究中发现的独立正确性修复：一元解引用错误缩窄索引，见 [说明与实板结果](POINTER-STRIDE-WIDTH.md)。新性能机制尚未实现；下面的手工源码对照用于判断方向，不计作 MX251 的新增优化收益。

## STC-IDE 实际做了什么

下表行号对应本机 `compiler-readable.js`，以证据文件中的哈希绑定。

| 机制 / 入口 | 实际行为 | 对 MX251 的意义 |
| --- | --- | --- |
| `specializeCallSites`，约 26391 行 | 为固定数组地址的指针实参克隆函数，将指针访问改成固定对象加游标；未再使用的通用版本可删除。排除部分库、变参、指针写入等情况，也不接受普通 EDATA 数组特化 | 最有价值的是调用点携带对象信息；不应为每个字符串都复制大型函数 |
| `specializeConstArgs`，约 26171 行 | 全部为常量的标量实参特化；本版本有函数体语句数大于 30 且不超过 40、每函数最多 4 个/全局最多 32 个版本等条件 | 属于有限特化，不是通用、无限制的全程序常量优化；MX 已有所有调用点一致常量的特化 |
| `applyRegAbiCostModel`，约 17846 行 | 遍历可达调用者，发现参数/返回寄存器与调用者命名局部寄存器冲突时切到静态内存参数块 | 名称虽含 cost，选择依据主要是冲突，不是最终机器字节比较；不能直接认为比当前调用保存方案更优 |
| `qEnsureDataOverlay`，约 25150 行 | 按调用可达关系、ISR 上下文和递归情况，为参数/返回块复用 DATA 存储 | 是内存块与调用图联合分配；不是单纯关闭 stack-auto，也不是新的 MX 大收益证据 |
| `runOptimizePasses`，约 17000 行 | 多轮常量折叠、不可达/无用代码删除、寄存器常量、无用加载与窥孔 | MX 已有多项对应能力，应比较缺失模式而非重复建一套 pass |
| 发射后流程，约 39145 行 | 包括循环地址寄存器提升、调用保存整理、栈槽往返消除、尾调用、局部指令合并等 | 寻址和运输是共同主题；存在某个 pass 不等于样本已获得收益 |

STC-IDE 默认还能发出 AI8051U MDU32 硬件运算。MX251 已有原生整数运行库和目标配置，不把它列为待补空白能力。

## 完整工程编译参考

STC 字节数由 HEX 实际数据重计，与其 `memReport.rom` 一致。下面用于辨别研究方向；STC 镜像没有实板运行，ABI、启动和地址空间选择也不同。

| 工程 | STC-IDE / B | MX251 修复后 / B | Keil / B |
| --- | ---: | ---: | ---: |
| p080 TFT | 30543 | 20485 | 18071 |
| p087 USB CDC | 4758 | 4581 | 3531 |
| p091 USB MSC | 7343* | 5651 | 4401 |

`*` p091 的 STC 编译报告把未解析的 `UsbBuffer` 另行分配，并对 13 字节聚合值到指针的转换发出警告，因此该项不能进入语义等价的体积排名。p080/p087 也有隐式窄化自动改写和共享变量等报告，原始报告已经保存。

另编译了 p068：STC 为 9563 B，Keil 为 3381 B；现存 MX 的 4455 B 来自较早工具链，本轮没有重建，故不混入上表。

STC-IDE 在独立样例中明确报告把 `data/idata/pdata` 归一成 EDATA，造成其直接寻址编码与 Keil/MX 不同。因此它适合作为机制参考，不能把其源码中的优化名称当作领先体积的证明。

## 指针实验：已知对象有多少价值

三个独立小型 C 函数分别计算数组和、移位混合以及配置字段分支。通用版接受指针，绑定版在源码里直接访问同一个全局对象；计数输入为 volatile。两版算法相同，但绑定版是研究时手工生成的源码变体，不是 MX 或 STC 自动优化结果。此项只测代码体积。

| 模式 | MX 通用 → 绑定，函数 B | Keil 通用 → 绑定，函数 B | STC 通用 → 绑定，整镜像 B |
| --- | ---: | ---: | ---: |
| 数组累加 | 55 → 40 | 28 → 28 | 194 → 126 |
| 数组混合 | 57 → 42 | 32 → 32 | 196 → 128 |
| 配置字段 | 98 → 49 | 43 → 35 | 225 → 175 |

MX 对这些模式的潜力为 **26%–50% 的函数体缩减**。STC 列包含整个镜像，不能与另两列横向计算函数优劣。本轮通用指针样例没有观察到 STC 自动取得手工绑定版的同等结果。

Keil 的数组通用版与绑定版同样小，说明它并不依赖逐对象克隆：直接保留地址寄存器，使用原生间接寻址并复用循环中的扩展值。MX 则仍有指针搬运、偏移形成和高位规范化成本。仅把函数绑定到对象也没有消除 MX 与 Keil 的全部差距。

### 放回真实工程

上一轮最终汇编中的符号地址传参点：TFT 36 处、CDC 1 处、MSC 17 处、双 CDC 1 处。TFT 包括字符串和位图，MSC 包括 SCSI 与拷贝接口。这是候选覆盖，不是可删除指令数。

指针高位掩码分别为 48/5/15/6 条，占 192/20/60/24 B；很多有实际语义作用，不能全部删除。固定四指令字段寻址模式在这些最终工程中没有匹配，所以独立字段样例的 49 B 潜力不能直接外推成工程收益。

TFT `Gui_Drawbmp16` 原为 257 B，Keil 为 91 B；本轮索引正确性修复后为 261 B。当前宽后端不接受相关 `_BitInt(24)` 整数转换，整函数退回旧后端。下一步可以从这类真实、可解释的缺口进入统一寻址，而不是继续添加孤立的字段窥孔。

## Keil 差额仍集中在哪里

统计上一轮链接后的应用函数指令，不含字库、常量和运行库。分类为诊断用途，不代表这些字节都能消除；Keil 的部分栈间接寻址会归入普通 MOV，因此分类不能机械相减。

| MX 应用指令类别 / B | TFT | CDC | MSC |
| --- | ---: | ---: | ---: |
| 普通搬运 | 3454 | 1707 | 2049 |
| 栈访问/调整 | 1751 | 230 | 344 |
| PUSH/POP | 1570 | 300 | 368 |
| 调用 | 964 | 416 | 600 |
| 分支 | 460 | 824 | 865 |

TFT `Show_Str` 716/390 B、`Test_Read` 580/277 B、`Fill_Triangel` 877/660 B、`LCD_ShowChar` 592/417 B（MX/Keil）。三种中文字体函数已共享，合计 884 B 对 Keil 1071 B；不能把共享主体单独拿去和一个字体函数比较，误判为退步。

CDC `uart_set_baud` 为 345/230 B。Keil 沿常量差值链做减法比较并共享赋值尾部，MX 仍有多次宽常量装载和远跳板。单做差值链估算约几十字节，属于次级方向，不足以独自填平工程差距。MX 已有公共尾部合并与分支收敛，后续要针对其不能表达的控制流形态。

## 下一轮的实施边界

1. **先做统一地址表示及偏移降低。** 保留基址来源、地址空间、索引的 C 语义宽度和常量偏移，允许只用于地址的 24 位偏移进入原生寻址；对循环争取一次形成基址、按步长更新游标。不要把任意 `_BitInt(24)` 运算简单当成 32 位运算，否则其回绕和符号语义会变化。
2. **再接调用点的地址信息。** 使用现有构建反馈带入地址空间/固定对象摘要，优先保留通用函数的紧凑代码；只有计算上值得且版本数量受控时才做私有特化。不能按 SDK 函数名选择，也不能逐字符串盲目复制 `Show_Str`。
3. **按完整工程净变化决定扩展。** TFT/MSC 分别覆盖循环与协议/拷贝，已有最终工程足够初筛。如果只消除少数掩码或重现旧字段原型的 1/14 B，就不继续扩大验证。地址表达式执行正确性复用本轮夹具并补实际新增的语义范围。

不重做：整函数寄存器偏好、连续单出口循环拆分、全量小函数内联、简单静态局部 overlay，以及已经有实现的 MDU32/公共尾部合并。它们各自已有记录；STC 出现类似机制并不推翻原实验结论。

本轮没有改变 SDK。体积台账仍是历史最佳候选组合的 40 个达到 120%、其中 18 个达到 110%；没有新增完整工程体积和时间双达标项。
