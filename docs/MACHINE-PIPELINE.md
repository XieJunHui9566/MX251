# 共同机器指令层、局部地址展开与整数运行库接入

2026-11-09，基于 `ce02cc7`，实现分支 `codex/machine-instruction-pipeline`。实现提交为 `c49ae62`、`0156fca`、`41cab4c`；原始 SDK C 文件未修改。输入、固件、编译器、计时数据和构建凭据见 [machine-pipeline-evidence.json](machine-pipeline-evidence.json)。

本轮 TFT 完整镜像首次低于 Keil 的 120% 体积线。110% 的完整工程体积与运行时间目标仍未达成。

## 完整工程结果

同一开发编译器，small/speed、标准 SDK 输入、函数裁剪与已有函数共享。MachineIr 列同时包含共同机器指令分析、静态调用反馈和局部地址展开。Native 列再开启原生整数库；它不会改动应用函数的公开 ABI。

| 工程 | 父版 / B | MachineIr / B | MachineIr + Native / B | Keil / B | 本轮采用 / Keil |
| --- | ---: | ---: | ---: | ---: | ---: |
| p080 TFT | 22093 | 21848 | **21544** | 18071 | **119.22%** |
| p087 USB CDC | 4769 | **4745** | 4850 | 3531 | 134.38% |
| p091 USB MSC | 6312 | 6110 | **5922** | 4401 | 134.56% |
| p095 双串口 USB | 6615 | **6595** | 6727 | 4830 | 136.54% |

采用配置分别减少 549、24、390、20 B。Native 在 p087/p095 增加 105/132 B，因此保持独立开关。表中的加粗组合不是一组统一默认参数；没有重新运行全 SDK。Keil 全工程分母沿用已有同模型台账，本轮新增的是同源码内核的 Keil 重编译与实板时间对比。

最终 ASM/RST/HEX 归因显示：

- TFT `Fill_Triangel` 从 1276 降到 1002 B，辅助函数 `_swap` 的 41 B 定义也被裁剪。展开按函数体和实参类型判断，没有使用函数名匹配。
- MSC `flash_writesector` 从 328 降到 184 B，其中 PUSH/POP 从 148 降到 8 B。主要变化是识别文件内 `_shift` 的真实寄存器破坏集合，而非把它当成未知调用。
- TFT 剩余大函数仍包括字体共享主体 772 B、`Show_Str` 741 B、`Test_Read` 666 B；USB 控制函数仍有字节运算和传参开销。机器层清理没有消除这些差距。

## 已落地的共同路径

`machine_ir.h` 将两个生成器的实际指令转为同一表示，记录寄存器字节范围、控制流、读写集合、相等关系和常量。普通后端与宽后端在最终成本比较前调用它，执行复制传播、目标寄存器合并、无用搬运删除和部分重复比较折叠。

这是**分配之后的物理指令层**，还没有替代两个后端各自的寄存器分配器。它提供共同的实际指令优化入口，不能描述为“已统一全部后端”。指令标志以 [TSC80251 Programmer's Guide](https://www.keil.com/dd/docs/datashts/atmel/tsc251pg.pdf) 为依据；例如 CJNE 同时写 CY、N、Z，替换为 CLR C 前检查后续 N/Z 使用。

调用反馈升级为按编译单元提供的 v2 格式：全局与静态名字分别绑定。机器层消费的保存事实也进入最终实际调用检查；若再次分配扩大了 callee 写集合，构建只更新相关调用者。旧 v1 格式及未开新选项的构建仍可使用。

局部地址展开复用已有前端的参数求值、作用域和返回处理。符合条件的小型静态函数只通过指针参数读写普通标量；调用点传入自动变量地址时展开，使后续优化重新看到直接读写。实际测试覆盖两个参数指向同一个对象、内层局部变量与外层同名以及 TFT 原样算法的八处调用。外部内存指针调用仍可保留原函数。

`NativeIntegerRuntime` 将已有原生 32 位乘除余库接到普通 small/stack-auto 工程。只有编译器运算辅助函数改用既有 ABI4，应用函数和 SDK 接口不迁移。构建同时保留定长整数格式化优化；否则额外运行库会触发旧的格式化库清单限制，让 TFT 回退到完整 printf 库，抵消整数路径的收益。原生整数库本身没有改写。

## 实板时间

AI8051U-34K64、STC-Link1D，自动发现串口 COM13。40 MHz、Timer0 mode1/12T，每 tick 为 0.3 μs，计时期间关闭中断。四份固件各有 128 个用例；串口结果均通过独立 Python 算术模型，无计时器溢出。每个用例采样多轮，取中位数，再累加 64 个用例。

| 计时工作负载 | 父版 tick 总和 | 新版 + Native | Keil | 相对父版减少 | 新版 / Keil |
| --- | ---: | ---: | ---: | ---: | ---: |
| SDK 原样三角形算法 + LCD 追踪回调 | 15051 | 11071 | 8570 | **26.44%** | **129.18%** |
| 合成字节控制流、私有调用、地址别名 | 12441 | 10163 | 9492 | **18.31%** | **107.07%** |

Keil 为 C251 5.60，SMALL、ROM(HUGE)、OPTIMIZE(7,SPEED)。三方使用同一套 C 文件、输入和时钟。LCD 追踪回调与 SDK LCD 单元一样使用普通宽后端，UART/计时器单元单独使用 legacy。四个镜像的结果分别有 635/642/630/648 个有效帧。

这些是内核时间，包含同一份 C 追踪回调；不代表完整 TFT 刷屏或 USB 吞吐。字节工作负载的 64 个时间用例均在 Keil 110% 内，但它是合成内核，不能增加“完整工程双 110% 达标”数量。早期 `board-project-07` 将追踪回调混在 legacy 单元，时间比例由本页 `board-project-11` 结果替代。测试板最后保留新版测试固件。

```powershell
./Build.ps1 -ProjectPath E:/path/to/project -FunctionSharing -MachineIr -NativeIntegerRuntime
```

对应 CMake 变量为 `MX251_FUNCTION_SHARING`、`MX251_MACHINE_IR`、`MX251_NATIVE_INTEGER_RUNTIME`。Native 当前用于 standard/small/stack-auto；p087/p095 的本轮采用配置省略该选项。新开关默认关闭。

复现内核使用 `tools/research/machine_pipeline_fixture.py create --source <SDK gui.c> --output <新目录>`，随后用对应开发 core 构建。Keil 编译每个 `.c` 时使用上述选项，链接使用 `CASE CLASSES(EDATA(0x0-0x7ff),HDATA(0x0-0x7ff))`；`capture --hex <固件> --output <新目录>` 自动发现设备、烧录并校验串口结果。

下一处有数据支持的工作是三角形循环中的跨调用活跃值、栈位置与运算辅助函数的寄存器分配。它距离 Keil 时间仍约 29%，而本轮字节内核已接近时间线；不能再用统一扩大寄存器池或全量小函数展开代替这个区分。
