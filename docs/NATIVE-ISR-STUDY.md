# 原生中断函数体原型：暂不采用

2026-11-11，基线 `8f9893b`。原型把 bank0 C 中断函数体接入现有宽 MIR，使用完整中断入口、共同 RETI 出口、已有现场保存分析和完整函数成本选择。没有修改 SDK。

六个完整工程 p032、p045、p049、p074、p136、p146 均构建成功，最终 HEX 字节数全部与推荐版相同。接着复用原编译参数和调用反馈，只编译全部 75 工程中含 ISR 的 73 个源单元，73/73 成功；仅三个函数选择新路径：

| 工程/函数 | 原函数/B | 原型/B | 减少/B |
| --- | ---: | ---: | ---: |
| p089 / usb_isr | 154 | 150 | 4 |
| p096 / usb_isr | 177 | 169 | 8 |
| p128 / usb_isr | 160 | 156 | 4 |

表中是编译器完整函数编码成本，尚未重链接对应三个工程，不能作为完整镜像收益。未进行硬件测试或全量矩阵重建。

实际原因：UART 中断多为字节状态处理，宽后端访问和寄存器准备反而更多；p074 的 DMA ISR 为 377/340 B，p136 的 I2S ISR 为 284/261 B。p045/p049 仍受有序汇编操作的导入范围限制。普通宽指令后端整体接入，并不能自动消除中断与 Keil 的差距。

本轮不把原型纳入推荐编译器。保存了 [原型补丁](../tools/research/native-isr-bodies.patch) 和 [证据索引](native-isr-study-evidence.json)；补丁基于 `8f9893b`，混合换行仓库可用 `git apply --ignore-space-change` 恢复。研究目录为 `E:/STVAPP/MX251-mainline-20261111/native-isr`，包含两版核心、六项试编和 73 单元筛选命令及结果。

另一个现成选项是 16 位立即数比较：基线 23 工程有 63 处紧邻的 `MOV WR,#imm; CMP WR,WR`，共 378 B；直接比较每处通常减少 2 B。连续同对象写后读只有 7 工程、21 处、63 B 的读取指令，暂不为此扩展内存优化框架。下一项先验证并默认启用已有立即数比较能力。
