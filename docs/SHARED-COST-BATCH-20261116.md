p131/p132 的增长均来自 main。旧版选择只折叠数据地址的3处访问；新版把CODE读取一起纳入5处访问的候选后，因循环成本增加而拒绝整个候选，失去了原来的数据地址折叠组合。最终代码的CODE拷贝循环也增加了地址计算。这是通用优化组合的选择缺口，不是库函数增长，也不因仍低于Keil而忽略。后续应保留已有数据地址方案，再独立评估CODE方案；本批候选不替换默认核心。

p059 的 Sample_Display 从旧后端切换到wide：选择时指令数41→40，字节85→93；最终函数81→89 B，Sample_RTC另省1 B，整包净增7 B。这是现有后端选择对指令数和体积的权衡，不能据指令数直接宣称运行时间改善。

## 通用改动

- 共享输出库：将 printf→puts 的取舍推迟到完整链接后，比较两种完整固件，保留更小版本。只对同时链接标准 puts/printf 且存在自动改写的工程试编。
- 本批共享输出库选择：32项改用共享printf、13项保留puts；相对同一编译器选择前的固件共省 1454 B。
- 构建复用：源码与头文件、工具及配置锁、参数、反馈内容相同的编译调用在同次构建内复用。最终所选构建日志记录 20 次复用；不引入跨项目持久缓存。
- CODE 索引：将常量表的符号地址保留到访存发射，减少循环中的地址活值和栈搬运，保持原读取空间与宽度。
- 指针对象：常量地址直接按三字节布局写入，普通写入使用字指令，volatile 写入保持原来的逐字节顺序。
- 位与中断：相邻的单用位逻辑更新直接读写进位位，保留端口读行为；把间接写入的原始 IR 信息交给现有保存分析。未知地址和核心寄存器别名继续保存完整上下文。
- 浮点调用：识别编译器自身的 binary32 运行库符号，复用已有 ABI 参数/返回值传递，并允许完整函数比较后端成本。支持能力不等于强制选用较大实现。
