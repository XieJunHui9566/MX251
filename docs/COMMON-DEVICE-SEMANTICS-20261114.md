## 架构与器件边界

目标注册表升级为 schema 3。架构统一提供 CODE 读取、对象寻址及有序操作策略；器件通过 `deviceEffects` 描述 SFR 布局、外设位和内存状态位作用，不能另存一套编译优化开关覆盖架构。没有外设描述的新器件仍继承通用能力，不继承其他器件的位表。
算术和调用优化继续使用既有通用路径；本轮没有改 SDK、函数名匹配规则或编译器发射代码。
新增的第三个目标名称仅用于测试配置继承和纯 C 代码一致性，不表示已支持第三颗实际器件。

STC32G EAXFR 的依据是厂商 [STC32G 系列技术手册](https://stcmicro.com/datasheet/stc32g-cn.pdf) 第 12.1 节，印刷页 576 / PDF 页 616。EAXFR 控制独立的 0x7E0000–0x7EFFFF XFR 区；EDATA、栈和内部 XDATA 位于其他地址区。由此接入现有 memoryStateBarrier，指令位置、内存和移动屏障保留。证据与文件哈希见 `stc32g-memory-state-evidence.json`；这不是本轮 STC32G 实板验证。

## 新发现的既有正确性缺陷

AI8051U 实板执行 768 组：**704 组匹配，64 组失败**。失败全部来自 bits_messy，所有 64 个输入均能复现。测试保留失败状态，不把编译成功写成运行通过。
父版与本轮的隔离测试固件 HEX 逐字节相同，SHA-256：`6454c63a9db9cc681ec411b40bdcc760346f097740fa5c0cefd28216874c6165`。因此该缺陷先于本轮配置变更。
定位：旧后端 `gen_lower.c.inc:2402` 的 loadDptrFromOperand 在运行期指针装入 DPX 后，没有同步撤销固定地址记录。读取 alias->ready 把实际 DPX 改为 flags+0，后续 p->keep 应访问 flags+1，却因旧缓存跳过了地址重载。`u0.asm` 和串口原始帧均已保存。
下一步先修这一通用地址事实失效问题，以原失败用例验证；再处理成本择优未知指令，随后才扩展位域新后端覆盖。不能通过改写测试、SDK 或按函数名禁用优化绕过错误。

本轮没有实现位域新后端或基本块混合降级。后续局部降级接口仍需研究；当前数据明确区分语义回退、容量回退、成本择优及未回退但生成较大代码。
