# 函数实参保留整对象读取

2026-11-13，实现 `ec7987e`，分支 `codex/argument-object-loads`。

p122 从 **4785 → 4708 B**，为 Keil 的 **109.92%**，新增跨过 110% 线。统一 75 项结果为 **75/75 ≤120%、65/75 ≤110%**；10 项缩小、65 项相同、0 项变大，累计减少 **259 B**。

## 原因与实现

对剩余 11 项读取最终 HEX、汇编和冻结 Keil 函数段后，发现 p122 主循环/按键扫描、p136 播放处理反复出现普通 DATA 全局整数逐字节取样。MIR 导入 `SEND/IPUSH` 时把所有符号快照强制标为 `byteAccess`，把已有的原生字/双字读取能力丢掉了。例如一个 32 位值会先生成四次 4 B 的直接字节读取，再搬入参数位置；现有整对象读取只需一条 4 B 的 `MOV DR,object`。

本轮保留符号快照原有的访问属性。普通 RAM 标量可以使用已有宽度读取；每次调用仍在原 IR 位置建立快照，调用修改对象后继续重新读取。参数 ABI、栈布局、求值顺序、SDK C 源和运行库没有修改，也没有新增用户选项或函数名规则。原生 ABI4、普通 ABI2、栈参数及变参共用这条规则。

volatile 参数保留现有逐字节访问：寄存器参数低字节先读，栈参数高字节先读。显式 `VolatileDataWide` 也没有扩展到参数。最终后端选择仍比较整函数，短包装函数可继续选择更小的旧后端。
