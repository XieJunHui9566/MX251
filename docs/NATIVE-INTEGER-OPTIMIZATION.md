# 整数除余复用与原生运行库

2026-11-09，父提交 `8a3f5bb`，分支 `codex/native-integer-registers`。实现提交 `305d249`、`ca76928`，既有 volatile 检查器更新 `5d4429d`。数据和输入哈希见 [native-integer-optimization-evidence.json](native-integer-optimization-evidence.json)。

这轮获得了通用数值计算的明显收益，尚未改善完整 TFT、MSC 工程的体积。实现全部位于 MX251 后端及原生整数运行库，没有 SDK 名称、函数名称或路径特例，SDK 输入未改动。

## 实现

- 32 位乘法仍计算三个 16×16 部分积，指令数从 13 降到 10；占用寄存器改为 DR0、DR4、WR12，保留全部高位寄存器。参数、公开返回值继续使用 ABI4。
- 无符号除法同时留下商和余数，取余库成员调用这份共同计算。32 位被除数、8 位非零除数用三次硬件 16 位 DIV 计算，替代原来的低 16 位逐位循环。16 位被除数保留单次硬件 DIV 路径；更宽除数沿用原有算法。
- 后端在同一基本块内识别已经计算的 `q = a / b`，将之后的 `a % b` 改为 `a - q * b`。条件来自编译器内建算术函数身份和 MIR 操作数，不要求某个运行库额外返回余数，也不读取 SDK 信息。当前覆盖原生 ABI4 的有符号/无符号 32 位调用；操作数和商在中间被重新定义时不复用。实际内存取样和控制流保持原位置。
- 除余复用用于 speed 优化。size 模式保留原来的取余调用，避免为了少做除法而引入乘法库及额外指令。

除法在 DR12 中留下余数是配套运行库的内部约定，普通 C 函数 ABI 没有增加第二返回值。取余包装调用共用除法时比原实现多占 3 字节返回地址栈空间。调用反馈记录新增归档的实际写集合及依赖链，同时保留旧归档的摘要。

## 实板结果

继续使用 AI8051U、40 MHz、Timer0 /12T、UART 115200 的既有计时外壳。每项 64 个输入，多帧取中位数后汇总；下表 tick 都相对上一轮已采用候选。

| 工作负载 | 上轮 tick | 本轮 tick | 时间减少 |
| --- | ---: | ---: | ---: |
| 无符号乘除余流水 | 37375 | 22144 | 40.75% |
| 有符号定点校准 | 54563.5 | 16932 | 68.97% |
| 三角形绘制内核 | 10747 | 10624 | 1.14% |
| 字节控制流 | 10163 | 10163 | 0% |

前两项组成的完整测试固件从 **1503 降到 1338 B（−10.98%）**。三角形测试固件从 2329 增至 2366 B；其时间相对已有合格 Keil 内核数据为 123.97%，仍未达到 110%。新增算术测试的 Keil 输出差异尚未解决，本轮不使用它作为性能分母。

新增 `wide-divmod.c` 覆盖同操作数除余、重复余数、不同除数、不同被除数、分支、volatile 再读取、独立除法/取余及有符号极值。数值、三角形/控制流、新增除余边界三组实板测试共 **384 个用例**通过，分别取得 616、638、633 帧。STC-Link1D 自动定位到 COM13；板上保留最终三角形测试固件。

单独改乘法寄存器的试验使数值固件 1503 → 1505 B，没有形成独立的大收益。只改运行库后的中间版本，有符号运算已明显加速，无符号流水因仍执行两次除法而稍慢。最终的后端除余复用消除了这项重复。相关中间产物保留在研究目录，不作为最终成绩。

## 验证和复现

- 6577 组操作数、13154 次独立指令模型执行：乘积低 32 位、商、余数、寄存器保留和栈效果通过。包含全部非零 8 位除数及 16/24/32 位除数路径。
- 运行库摘要逐成员重新汇编核对归档 REL，74 项写集合及调用依赖检查通过，包含应用覆盖无符号除法后向有符号取余传播。
- 除余变换在 small/large、speed/size 四种配置下通过检查；没有源码乘法的最小程序也能汇编新增乘法调用。
- 既有调用、常数乘法、溢出分配回归通过。volatile 检查器原先漏识别已存在的直接寄存器字节访问诊断；父编译器同样失败。更新解析后仍逐条检查实际 MOV 和事务顺序，四种配置通过。
- 共享机器层模型 178 个程序、11392 次差分执行通过。
