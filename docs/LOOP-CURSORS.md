## 实现

`wide_loop_cursor.c.inc` 同时识别独立的 `base + index` 节点及已经折入内存访问的 `addressOp/addressIndex`。对于循环私有的已知对象基址，直接复用该值作为游标；每次迭代结束加 1，并沿用原生指针运算的 24 位掩码。原计数器更新、退出条件、返回值及每条内存访问的顺序保持原样。

第一版处理从零开始、步长为 1、常量上界的无符号 8/16 位计数循环；对象范围覆盖全部访问。循环是直线体、单入口、单回边、无调用，基址在每次进入前重新形成，循环外没有消费者。普通 XDATA 与目标允许的平坦 CODE 都可参与。同一基址的多个访问共用一个游标；当前每个循环最多 8 路。变长边界、计数回卷、指针参数、volatile 字节访问及其他控制流仍使用现有生成路径。

CODE 字节直读只标记在本次循环候选的访问节点上，同时要求 `--mcs251-flat-code-reads`。因此它与游标的寄存器分配和总成本一同选择，不会把全工程的字节表读取切换成原生 MOV。

候选经过完整重新分配、函数字节数、加权指令成本及栈帧比较。新增 `wide_cursor_cost.c.inc` 对改写的内层循环逐项比较指令、搬运、内存和栈操作数；循环外的指令必须相同，仅忽略注释、空白和发射器私有标签编号。这使事件循环里的内层复制也能比较，无需扩建原来只识别非嵌套循环的成本模型。计数是静态成本依据，不冒充芯片周期。

默认开启；`MX251_LOOP_CURSORS=0` 可作消融对照。已有默认关闭的 affine 原型不变。

## p074 完整工程

原来的每个循环有四路重复地址生成，CODE 还经 DPX/MOVC 读取。现在四个既有基址直接作为游标，CODE 字节使用原生 `MOV Rn,@DRm`。两个循环及最终布局的总收益为 **62 B**，`main` 为 **323 → 261 B**：整工程 **1149 → 1087 B**，Keil 为 **909 B**，本版比例 **119.58%**。

研究阶段的 60 B 是独立片段估算；这里的 62 B 来自最终链接 HEX，包含后续指令整理及布局效果。实现中候选选择器的 333 → 265 B 是进入后续机器整理前的函数计价，也不与最终函数字节混用。
