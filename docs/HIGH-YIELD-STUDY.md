# 大收益方向筛选：对象与地址降级

2026-11-09，基于 `964d31b` 的完整工程结果。用户要求停止围绕几个字节继续打磨，寻找跨工程有效的优化。本轮没有改生产编译器；完成现有机器码归因，以及四个完整工程的小函数内联实验。指纹和结果见 [high-yield-study-evidence.json](high-yield-study-evidence.json)。

## 决定

下一项优先原型是**寄存器分配之前的对象与地址表示**：保留对象、常量偏移、地址空间和物理访问宽度，直接选择 DATA、CODE、EDATA/XDATA 与栈访问，再为真正需要计算的地址分配寄存器。

这是有明确覆盖对象的重构候选，尚无净收益结论。不能把下面退回函数的体积当成可删除体积，也不能承诺一个改动就达到双 110%。本轮实编译的全量内联方案增大了镜像，已停止扩展；没有生产优化提交或新增达标工程。

## 为什么不继续只改保存与溢出

当前四个完整镜像与同模型 Keil 基线：

| 工程 | MX251 / B | Keil / B | 达到 110% 仍需减少 / B |
| --- | ---: | ---: | ---: |
| p080 TFT | 23153 | 18071 | 3275 |
| p087 USB CDC | 4769 | 3531 | 885 |
| p091 USB MSC | 6312 | 4401 | 1471 |
| p095 双串口 USB | 6615 | 4830 | 1302 |

已选宽后端的寄存器分配结果中，TFT 有 7 个函数发生值溢出：`LCD_DrawLine`、`Fill_Triangel`、`LCD_ShowChar`、三个 `GUI_DrawFont*`、`Show_Str`。三个 USB 工程的已选宽后端函数均没有值溢出。USB 仍然存在传参、调用保存、局部对象和旧后端的栈访问；这个统计仅用于判断“释放更多宽后端寄存器”的覆盖范围。

`wide_register_choices()` 将 DR16/DR20 共八字节固定留给发射器，A/B 另有约束。回收这些寄存器需要把临时操作数纳入分配，不能只扩候选数组。它是 TFT 的后续候选，目前证据不支持把它作为 USB 的共同突破口。

## 一次导入失败影响整个函数

使用已有 `tools/research/call_layout.py` 读取最终 ASM/RST，并将指令字节与 HEX 对应。以下分母只含具有源码函数元数据的实际指令，排除常量、启动段及没有这些元数据的库函数。

| 工程 | 已归属源码指令 / B | 导入失败函数 / B | 占比 | 导入失败函数数 |
| --- | ---: | ---: | ---: | ---: |
| p080 | 12040 | 4478 | 37.2% | 14 |
| p087 | 4241 | 1460 | 34.4% | 12 |
| p091 | 5362 | 1965 | 36.6% | 18 |
| p095 | 5998 | 2012 | 33.5% | 12 |

这比继续调整已进入宽后端的几个调用点覆盖更广，但“进入宽后端”本身不等于变小或变快。

- TFT 的 `Test_Read` 666 B、`Test_Triangle` 577 B、`Test_FillRec` 454 B、`Rotate_Test` 441 B 等，受到 CODE/通用指针转换的整函数导入边界影响。所读位置是 `wide.c` 的 CAST 类型检查，不能从诊断的部分成本字段推算最终节省量。
- USB 的 `Ep0State` 是包含三字节指针字段的 DATA 结构体。`wide_extern_data_layout()` 只允许普通整数成员，`wide_near_field()` 也只处理整数 1/2/4 字节访问；结构体中存在指针字段会挡住部分直接成员访问。三个工程的对象/地址及间接内存两类拒绝分别覆盖 930、925、997 B。
- `usb_ctrl_in/out` 还涉及间接指针对象。当前 MIR 常用四字节寄存器值表示三字节指针，但直接字段、间接字段和 CODE 访问分散在不同入口，需要统一物理宽度与访问方式。
- `uart_polling` 等另有内联位指令的能力限制。它们计入总覆盖，但不是对象与地址原型会自动解决的部分；本轮没有改变器件能力判断。

仅移除 CODE 转换检查的 `flat-pointer-cast-v1` 历史实验已使 p078/p080 分别增长 163/62 B，见 [调用布局筛选](CALL-LAYOUT-FEASIBILITY.md)。本轮没有重跑它。

## 已实编译排除：全量小函数内联

问题是假设跨函数的传参、保存和常量损失才是大头。为先测价值，使用独立工程副本把选定函数的**原样函数体**移到原头文件声明处，标为 `static inline`，复用现有前端展开；不重写算法或外设事务。原冻结输入没有修改。

- USB：`usb_read_reg`、`usb_write_reg`。原镜像的读/写静态调用数分别为 p087 13/61、p091 12/50、p095 18/90。
- TFT：`LCD_write`、`LCD_WR_REG`、`LCD_WR_DATA`、`LCD_WR_DATA_16Bit`。
- 全部沿用父版编译器、small/speed 配置、标准运行库及正常 CMake 构建入口。

| 工程 | 原镜像 / B | 全量内联实验 / B | 变化 / B |
| --- | ---: | ---: | ---: |
| p080 | 23153 | 24124 | +971 |
| p087 | 4769 | 4914 | +145 |
| p091 | 6312 | 6459 | +147 |
| p095 | 6615 | 6823 | +208 |

TFT 中 `LCD_Init` 从 471 增至 1046 B，三个字体函数各增加 63 B。USB 同时有缩小和增大的调用者，不能按函数小、调用次数多就全量展开。

为区分展开本身与后端选择，仅对 p087 补做两次对照：原输入全部用旧后端为 4802 B（+33）；内联副本全部用旧后端为 4743 B（−26）。旧后端能改善部分控制函数，但 `uart_set_baud` 又从 349 增至 495 B。因此不全局切后端，也不据此建设大规模自动内联系统。

这些是研究副本的完整镜像体积，不计入冻结 SDK 成绩；没有下载或测量运行时间。个别旧后端函数变小的字节也不能直接累加，因为调用破坏集合和调用者保存成本会改变。

## 下一原型的具体边界

先处理“符号对象＋偏移”的访问表达式，并将三字节指针对象与四字节 MIR 计算值分开：

1. DATA 结构体内普通字段与指针字段共用对象布局事实；访问整数成员不再因相邻指针成员而拒绝。
2. 三字节指针成员按三字节读写，CODE 来源、通用指针和访问地址空间保持区别；直接地址不先绕成临时宽指针。
3. 用同类操作的小样例与 USB 控制函数、TFT 字符串调用者测第一轮完整镜像。先看新表示是否减少地址物化及整函数回退，再决定扩大覆盖或接着重构分配器。

首轮不扩 ABI、不改 SDK 接口、不重跑 105 工程矩阵。对完整工程仍只有个位或几十字节收益时，就不把这条原型当作大收益方案继续打磨。只有取得明显净收益，才进入对应机制的硬件与运行时间验证。
