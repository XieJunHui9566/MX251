# 高频叶函数的寄存器传参试选

2026-11-09。当前生产编译器不变，新增可直接使用的研究构建工具：
[selective_leaf_abi.py](../tools/research/selective_leaf_abi.py)。它从完整基线找出高频双整数参数叶函数，使用编译器已有的 ABI4 重新构建完整工程，并按实际 HEX 字节数选择结果。SDK 源文件没有改动。指纹、输入一致性及执行记录见 [证据](selective-leaf-abi-evidence.json)。

## 实际收益

| 工程 | 基线 / B | 试选后 / B | 减少 / B | 减少比例 |
| --- | ---: | ---: | ---: | ---: |
| p087 USB CDC | 4769 | 4617 | 152 | 3.19% |
| p091 USB MSC | 6312 | 6208 | 104 | 1.65% |
| p095 双串口 USB | 6615 | 6388 | 227 | 3.43% |
| p080 TFT | 23153 | 23153 | 0 | 0% |

三个 USB 工程按同一规则都选到 `usb_write_reg`，静态调用数分别为 61、50、90。工具不含这些工程名或函数名。每个工程全部源码输入、编译器、目标配置和构建选项与基线相同。p087 由新工具完成自动选取、完整编译及最终绑定检查；另外两个先以同一契约完成实编译，再用新工具的规则及最终机器码核对。

p080 唯一同类叶函数 `LCD_write` 仅有四个静态调用，未达到本轮的传参开销筛选值，因此没有重复构建 TFT。此方向是调用密集工程的收益，不能称为所有工程都受益的大幅突破。

## 与已关闭的全量 ABI4 迁移有何不同

Keil 对照来自原始 p087 的 `usb.c`、`usb_req_std.c`、`uart.c`，用本机 C251 5.60、SMALL、ROM(HUGE)、OPTIMIZE(7,SPEED) 生成 SRC。`usb_write_reg` 用寄存器接收两个字节；MX251 普通 ABI2 的第二字节走栈，每个调用点需要压栈及清栈。本轮复用现有 ABI4，只迁移一个调用密集的叶函数，保留其余函数和运行库的约定。

把 `usb_read_reg` 同时迁移后，p087 为 4642 B，比仅迁移写函数多 25 B。单参数函数没有第二参数出栈的共同收益，因此不扩大名单。Keil 还会直接用位跳转实现部分整数提升后的掩码判断；当前 USB 宽后端中这类扩宽掩码判零只有四处，未为此另开编译器原型。

已有的全量迁移失败结论仍成立。本次不修改其历史记录，也不把不同父版的节省相加。

## 工具规则与使用

输入是已有的完整构建目录、同版 core、原项目以及可选的 CMake 输入清单。当前范围为 standard runtime、普通 stack-auto C 单元、无项目归档。只选择两个整数参数、唯一导出定义、无取址/间接入口、没有内部调用的叶函数。引用来自最终 ASM/RST/HEX；调用签名、实际 ECALL 目标、启动入口和库引用一起参与选择。原 function-GC 根保持保留。

按可确认的压栈和清栈静态字节数排序，默认至少 64 B，只构建首选的一个候选。这是限制试编译成本的筛选值，不是净收益预测。内部契约使用现有 `MX251-INTERNAL-ABI4-V2`；源文件不插入属性，最终符号由编译器正常修饰。完整链接更小才在 `selection.json` 中选用候选，否则指向原基线；不覆盖原基线、默认发行 core 或 IDE 配置。

```powershell
python tools/research/selective_leaf_abi.py `
  --baseline <完整构建的latest目录> `
  --core <同版core目录> `
  --project <原mx251.json> `
  --cmake-input <该工程的mx251-inputs.json> `
  --output <新的试选结果目录>
```

直接列出全部 files/units 的项目可省略 `--cmake-input`。结果目录保存契约、构建日志、完整候选及选择记录；`selectedBuild` 指向实际选择的构建目录。工具是显式研究入口，尚未接入默认构建流程。

## 验证及实际限制

四项选择器检查通过，覆盖完整调用配对、地址取用、库/启动入口、重复定义、非叶函数和不同 ABI。三个完整 USB 镜像都核对了输入一致性、最终修饰符号、ABI4 定义及每个 ECALL 的实际目标。

[跨文件测试](../tools/research/leaf-abi-fixture/)使用两个字节参数、字节返回值、volatile 参数写入，并让调用者的 x/y 跨越连续 16 次调用存活。该测试的 ABI4 候选反而从 1016 B 增至 1090 B，自动选择正确保留了基线；它同时是实际的不收益样例。为检查传参执行，本轮单独下载了此候选。

STC-Link1D 通过本次 HID/串口枚举定位，AI8051U-34K64 实板收到 1867 个完整 LAF1 帧，覆盖全部 256 组输入、每组 16 个调用结果，与独立主机计算全部一致。捕获检查器为 [check_leaf_abi_capture.py](../tools/research/check_leaf_abi_capture.py)。设备保留本次测试固件。

USB 整工程没有在本轮执行测试，也没有取得整工程运行时间比值。三个镜像仍高于 Keil 的 110% 体积线；没有新增双 110% 达标记录。当前可保留的是 104–227 B 的明确收益和自动试选能力，后续主线仍需要更大的结构性收益。
