# 基础标准库重建与本轮收口 · 2026-11-16

本轮只重建 `__memcpy`、`memset`、`strlen` 三个已有标准函数。原始 C 算法不变，把此前已经完成的通用后端优化应用到标准库；不增加 SDK、工程编号或器件专用分支。

## 实现与单元体积

新配方更新显式候选核心的 small/large stack-auto 标准库，并同步维护启动、格式化和目标配置中的归档哈希。每种库的其余 138 个成员逐字节相同，公开符号一致，ABI2 和四字节 size_t 保持原有接口。源码、配方、编译器及归档哈希随核心保存。

| 成员 | 原来/B | 重编/B | 减少/B |
| --- | ---: | ---: | ---: |
| `__memcpy.rel` | 207 | 72 | 135 |
| `_memset.rel` | 141 | 66 | 75 |
| `strlen.rel` | 96 | 43 | 53 |

两种模型的单元结果一致。只有实际链接这些函数的程序会得到对应收益。

对照和本版使用同一编译器、同一应用源码及配置，只更新候选标准库与对应哈希。Keil/STC-IDE 使用已有参考，不把历史版本与本次对照的差额算入本轮。

## 验证与剩余限制

- 两种标准库的编译、归档替换、导出符号及未修改成员检查通过；四组完整固件 A/B 均完成到最终构建返回。
- 独立测试使用动态长度和填充值，覆盖 0、1、255、256、257、319，返回指针、完整目标区及边界哨兵、填充值的低字节截断。读写覆盖 DATA、EDATA、XDATA，复制和 strlen 也覆盖 CODE。
- 主机执行 128 个测试用例通过，用于验证测试逻辑；它使用主机标准库，不能证明目标代码正确。
- 目标测试固件：small 2257 B、large 2340 B；两份最终链接图均确认使用三个更新成员。large 的有效目录为 board-large-model，早期 board-large 实际仍为 small，不计作第二种模型。
- 实板仅尝试一次。识别到 STC-Link1D，目标握手在 5000 ms 后超时，eraseAttempted=false、configurationAttempted=false；没有取得目标执行或计时结果。此次不继续研究下载链路。
- 尚未替换默认核心。本候选继承上一轮纯文本 printf 改动，上一轮 p123 增大 22 B 的记录仍然有效，不因本轮其它程序缩小而抹去。

## 收尾条件

本批实现和离线对照完成，到此停止追加优化。目标板执行是明确待办，不把它记成已通过，也不自动转入下一项优化。

最终目标仍是生成体积与运行时间均不超过 Keil C251 的 110%，并达到实际工程所需的基本能力。目前不能据零散例程的体积收益宣布该目标完成。

进入整体验收时应冻结一个候选版本和测试集合：汇总已知错误与功能缺口，复用已有独立用户程序压力测试，统一记录整套工程的编译/体积结果，再补齐明确的实板语义和运行时间证据。未达到的项目逐项列出。其它潜在优化留到后续版本，不继续无限延伸当前批次。
