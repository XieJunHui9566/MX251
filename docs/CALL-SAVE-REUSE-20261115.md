## 实现

原代码在连续调用之间经常先恢复一组活值，紧接着又把它们原样压栈。本轮让这些值继续留在原保存栈中，直到后续使用点需要恢复；不新增局部帧，不改变调用参数布局。

- 发射器标记自己生成的保存、恢复和参数准备区。只有完整的物理寄存器组及栈顺序匹配时才连接；两区间的寄存器搬运不能读取或改写这些值，也不能观察 SP。
- 参数准备按指令顺序计算“覆盖前的读取”。常量参数先覆盖 ABI4 参数寄存器时，可以省去对其旧值的恢复；准备过程或被调函数入口仍会读取旧值时，保持原来的保存与恢复。
- 复用发生后同步扣除静态指令数与循环权重成本，参与原有寄存器分配、完整后端和调用约定择优。普通函数与 bank0 中断函数共用实现；没有器件、SDK 或函数名称匹配。
- 有序内联汇编、控制流边界，以及后续才提交的局部乘法替换区域保持各自的栈范围。延后替换不会拆掉其他调用正在复用的保存区。

收益不仅来自删除 PUSH/POP。固定反馈试算中，USB 的新后端从 1901 B 降至 1785 B，胜过旧后端的 1826 B；完整构建随后又应用已有的调用约定优化。g070 的 `LCD_SetWindows` 从旧后端 125 B / 47 条指令切换为新后端 91 B / 31 条指令。图形工程中的字符绘制、圆绘制和窗口设置也获得收益。

新增 `MX251_BACKEND_CANDIDATES` 诊断变量，可输出整函数择优前的两个候选，用于分析实际指令差异。
