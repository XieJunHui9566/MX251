## 修正内容

官方实验箱冻结输入的 `AI8051U.h` 明确声明 `SPH=0x85`、`ADC_RESL=0xBE`（分别为第 14、72 行）。此前后端沿用 `SPH=0xBE`，ADC 访问会阻断 ISR 保存精简；调用效果分析又将 0x85 当成 DPX 高部写。现在通过目标能力 `sph85-v1` 统一选择地址，适用于任意使用这一布局的目标，不依赖 SDK、工程或 C 声明名称。

- CLI：`--mcs251-sfr-layout sph85-v1`。省略时保留 `legacy-v1`；未知值报错。
- AI8051U 目标配置修订到 7，正常 CLI/CMake 入口自动传入能力。STC32 目标本轮不变。
- ISR、SFR 核心状态判断、公共代码提取、函数共享使用同一 SPH 地址。
- 编译器输出布局记录，调用效果、最终调用边界和 CFG 地址分析使用各编译单元的真实布局。0x85 写入不再被误报为只改 DPX。
- 构建命令、receipt、构建身份和 profile registry 锁均包含此次配置。

该能力只调整 SPH 映射，不声称覆盖芯片完整 SFR 表。寄存器依据为已冻结的官方头文件；在线官方产品页仅作为资料入口。原始 SDK、厂商 PDF、硬件身份和串口原始帧保留在外部证据目录。

## 下一处有共性的阻点

p136 的 `_I2S_ISR` 已越过 `mov _ADC_RESL,#0`，现在停在 `_Alaw_encode` 调用。其普通 C 函数将 `_voice_buff` 的符号地址装入 DR16，再加 WR14 的动态下标，最后 `mov @dr16,r9`。现有字节常量分析既不表达符号地址来源，也不能跟随这个动态加法；因此整个 callee 的写集合变为未知，中断仍保存全部寄存器。p136 仍为 4741/4128 B（114.85%），距离 110% 尚差 201 B。

对已有 75 项结果进行只读统计，`unknown-indirect-write` 出现在 **40 项、63 个函数**；未过 110% 的 p039、p045、p049、p074、p122、p136 均涉及。这是候选范围，不是预计可优化数量：其中含 main、参数指针以及确实未知的指针。

下一步先分类这些路径，优先评估“已分配数组符号＋有界偏移”的跨指令地址来源传递，让调用分析保留可证明的 GPR 写集合。先量化可以释放的调用保存和 ISR 保存，再决定实现范围；不按上述函数名添加规则。此次不以数组名称、SDK 预期或裸声明替代地址证明。
