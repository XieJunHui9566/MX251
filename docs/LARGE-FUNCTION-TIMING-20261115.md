# 用户代码实板计时、大函数差距与整数提升优化

2026-11-15。计时与归因工具 `c40ce24`；编译器及回归 `078a005`。
编译器 SHA-256：`e39acb8f67bb2bd8219a1643039348802375765f5067691608706c8b06f5f263`。

本轮建立 MX251 / Keil C251 同源用户代码实板计时，并修复整数提升后的常量除法/取模优化缺口。规则按编译器运行库身份、类型、常量和范围信息决定，没有 SDK、工程、函数或器件名条件。

## 已实现的通用优化

`(unsigned_byte + 1) % 16` 按 C 规则提升为 signed int，原先落到完整 `__modsint` 调用。现在复用现有隔离范围分析，证明被除数非负后，将编译器生成的 16/32 位、正二次幂除法/取模调用转换为移位/掩码。环形缓冲区两个调用点的范围均为 **1～256**。

规则处理已经取样的 MIR 值，不改共享 iCode，不重新读取对象。可能为负数的值、有符号截断后跨零的值、负除数继续使用原运算；只在匹配到相关运行库调用时按需计算范围。普通用户函数不按名称识别为运算。

用户环形缓冲区 `ring_clean`：

- 同源函数指令 **292 → 214 B**，减少 **78 B（26.71%）**。
- 64 个输入的计时中位数均从 **993 → 245 ticks**；结合烧录器校准频率，耗时减少约 **75.3%**。
- 相对 Keil 同源写法，从 **197.01% → 48.62%**。
- 本测试合并固件 **11152 → 11074 B**；Keil 为 **6124 B**。整份测试固件体积仍未达线，不能用这一条路径的速度收益代替体积验收。

## 同源实板计时

复用独立用户压力集的结构体、协议解析、环形缓冲区、位域、回调、大函数六类算法，各有 clean / messy 两种等价写法。函数体保持原样；为 C251 调整类型/地址空间声明的拼写，两套编译器收到完全相同的 C/H 文件。Keil 使用 XSMALL、OPTIMIZE(7,SPEED)，MX251 使用 small、speed、正式候选入口及默认优化策略。

AI8051U-34K64、STC-Link1D；Timer0 mode 1、12T，关中断。计时区包括分派、一次工作函数和结果搬运，串口输出在计时区之外。每种写法 64 个输入，每个输入至少 4 次采样，取中位数；另有 64 个空控制输入，控制开销约 0～1 tick，不作扣除，也不计入达标分母。

## 验证与官方工程范围

- small/large × size/speed × ABI2/4 共 8 组：每组 6 处优化，四类负数/截断/负除数边界的实际指令与父版相同；volatile 对象实际访问仍是一次写、两次有序读取。
- 新独立边界固件实板 **320/320**，每项内含 4 个输入，覆盖所有 byte 输入、16 位边界、32 位提升、负数、截断、负除数和 volatile 读取。固件 1664 B。
- 用户压力集 **63/63**，三个目标描述的纯 C 对象一致。相对父版只有九组 `ring.rel` 改变，其余 54 个对象相同；主机 3072 次求值、1536 对等价写法通过。
- 官方工程只重编 g133，仍为 **8591 B**，HEX 与父版完全相同。最终汇编中的相关运行库调用不足以证明其他构建候选都不受影响，因此本轮未更新全量 97 项成绩，也没有增加官方达标项的结论。

最近一次完整 97 项成绩属于父候选：Keil 110% 为 40/97、120% 为 70/97；STC-IDE 为 75/79、77/79。本轮没有把局部重编当成新版全量验收。

## 大函数归因与下一步

基于现有最终 HEX/RST/ASM 与 Keil LST/MAP，逐函数统计编码字节；下表是实际开销分类，并非可直接删除的字节。

| 函数 | MX / Keil B | 栈操作 MX / Keil B | 寄存器搬运 MX / Keil B | 观察 |
| --- | ---: | ---: | ---: | --- |
| g071 USB_ISR | 1568 / 934 | 214 / 28 | 237 / 36 | 中断入口/出口保存仅 48 B；主要差距在函数内部 |
| g070 GUI_DrawFont16 | 705 / 357 | 380 / 4 | 97 / 52 | 栈访问、参数及跨调用活值占比高 |
| g104 RX2_Check | 684 / 451 | 176 / 4 | 123 / 30 | 调用运输和寄存器搬运明显偏多 |

栈分类包含参数、调用保存和临时值，不等于 spill 数量。Keil 也可能以内存存放局部变量，不能把它的较小栈分类解释成“零访存”。归因工具核对 Keil 指令总字节与函数段大小，并单独标出不匹配。

独立大函数 `giant_messy` 在 **512 个中间值、515 个节点**时因 value-capacity 回退旧后端，生成 7243 B；Keil 对应 3947 B。这不是器件能力差异，而是固定 MIR 容量限制。其速度已经进入 110%，体积却仍明显落后。

下一步优先研究中间值按活跃期复用或动态容量，解除大函数整函数回退；同时以结构体/位域的重复栈访问和寄存器搬运为生成质量样本。应先量出新路径的收益和编译成本，再决定数据结构调整，不仅提高一个上限数字。
