# 通用字节拼接

2026-11-13，实现 `c97e181`，分支 `codex/byte-assembly`。

统一 75 项体积结果：**75/75 ≤Keil 120%、66/75 ≤110%**。相对上一版，15 项缩小、60 项相同、0 项变大，净减少 **175 B**。p136 从 4668 降到 **4635 B（112.28%）**。

## 改动

此前每个字节分别扩展到 16/32 位、移位，再作宽 ADD/OR/XOR。新 `WM_BYTE_PACK` 节点识别有效字节互不重叠的表达式，直接把取样值送到最终字节位置。支持两字节/四字节结果、大小端排列、重复输入字节和常量字节；被提前扩展的无符号栈参数也可作为字节来源。

只消除表达式内部的纯值计算。所有内存节点留在原处，读取次数、宽度和次序保持原样，包含 volatile 字节。删除共享中间值前检查其所有消费者都属于本次组合。重叠字段、符号扩展和改变含义的截断不按无重叠字节处理。

低寄存器结果使用并行字节搬运，先搬不会覆盖待用来源的字节，寄存器环用保留的 A 解开。上部寄存器或栈结果通过 B:A 与既有宽暂存寄存器组装。活跃信息和寄存器分配使用全部字节来源，变换放在现有中端变换之后、最终分配之前。

按完整函数的实际发射体积、加权指令数及栈帧选择，已知循环退步仍拒绝。循环比较器未覆盖的函数保留 `decision=-1` 诊断，采用上述整函数成本选择；**不把它记录为逐循环性能已证明**。仅本次字节拼接选择启用既有条件跳板归一化，其它变换的策略未改。`MX251_BYTE_PACK=0` 可重现父版指令。

首两次 p136 试点停留在 4668 B：候选函数已经更小，但被逐循环覆盖要求挡住。第三版使用前述整函数策略后为 4635 B。只对最终编译器运行完整矩阵，早期试点产物另存。

这是一项编译器中端/后端优化，没有按工程、函数名称或 SDK 算法匹配，也没有修改 SDK 输入。
