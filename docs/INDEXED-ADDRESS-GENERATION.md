# 通用下标地址生成

2026-11-13，实现 `482d089`，分支 `codex/indexed-address-generation`。

全部 75 项由同一编译器构建：**75/75 ≤Keil 120%、65/75 ≤110%**。相对 CY 修复统一版，22 项缩小、52 项相同、1 项变大，净减少 **106 B**。合计 **191722 / 192049 B（99.83%）**。

## 实现

- 动态 8/16 位下标直接在地址临时寄存器中扩展，再加驻留基址，省掉先复制基址的指令。使用原有符号扩展规则。
- 将相邻、单次使用的无符号 16 位乘 2/4 或左移 1/2 与地址计算合并，省掉缩放结果的往返搬运。先按原 16 位宽度运算，再扩展到指针宽度；`0x8000*2`、`0xc000<<2` 的截断不能推迟。
- 让普通 CODE 字节表进入已有的地址折叠路径，直接复用地址结果；读取仍走原 MOVC 路径。已有循环游标的统一 CODE 读取规则不变。

规则只依赖类型、用途和寄存器位置，不匹配工程、SDK 或函数名。参数值加载、调用和真实内存访问不被新缩放融合跨越。下标另有用途时继续保留它的值；volatile 的事务数量不变。正常构建默认启用；研究对照可用 `MX251_INDEXED_ADDRESS=0` 关闭新增路径。

本轮优化了重复扩展和地址搬运，没有进一步删除最终的 24 位地址掩码。Intel 手册要求间接地址 DRk 高 8 位为零；仅凭加数是指针和窄整数，不能证明相加后仍满足这一点。见 [8xC251 用户手册 §5.3.1.4](https://www.keil.com/dd/docs/datashts/intel/8xc251sx_um.pdf)。
