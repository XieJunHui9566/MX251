# Keil 窄整数对照与 MX251 改动

2026-11-09，父提交 `f83c4f1`，分支 `codex/narrow-integer-lowering`，实现提交 `4fc3cf1`。原始数据、收据、输入哈希和未采用试验见 [narrow-integer-lowering-evidence.json](narrow-integer-lowering-evidence.json)。

这轮采用两处通用后端改动。混合位宽计算实板耗时减少 9.37%，三角形内核减少 2.38%；完整工程收益仍较小。SDK 输入哈希前后一致，没有修改 SDK，也没有按工程或函数名称选择优化。

## Keil 对照和实现

使用本机 Keil C251 5.60，以 `SMALL ROM(HUGE) OPTIMIZE(7,SPEED)` 编译既有三角形测试输入，输出保存在 `E:/STVAPP/MX251-mainline-20261109/narrow-integer/keil/triangle.SRC`。Keil 将有符号 16 位数扩展到 32 位时使用连续两条 `MOVS`：

```asm
MOV  WR2,dy01?151
MOVS WR0,R2
MOVS WR0,R0
```

第一条 MOVS 将源字的高字节符号扩展成字，第二条再扩展其高字节，得到完整的 `0000` 或 `FFFF` 高字，同时保留原低字。

MX251 的 `wsign_word` 原先通过清零、比较、条件跳转和写入 `FFFF` 完成这个操作，现在使用 MOVS。低寄存器直接取字节；高寄存器没有字节别名，先借用发射器已有的 WR10 暂存，再完成扩展。汇编源操作数必须写 `r10`；此指令的汇编器不接受 `b` 别名。MIR 节点之间不依赖旧扩展序列留下的比较标志。

共享 Machine IR 同时调整等价值的寄存器选择顺序：优先使用已分配的高寄存器，避免仅因编号较小而保留 DR16/DR20 中的临时副本。这项改动在三角形固件中另外减少 2 字节，其余已测完整工程没有额外变化。

公开 ABI、SDK 和原生整数库均未变化。改动作用于现有宽后端和 MachineIr 路径，没有替换默认发布包。

## 实板与完整工程

继续使用 AI8051U、40 MHz、Timer0 /12T 的既有计时外壳，每项 64 个输入，按输入取多帧中位数后汇总。

| 工作负载 | 父版本 tick | 本轮 tick | 时间减少 |
| --- | ---: | ---: | ---: |
| 混合位宽有符号求和 | 42407 | 38431.5 | 9.37% |
| 全 int16 位模式散列 | 486208 | 486208 | 0% |
| 三角形绘制内核 | 10624 | 10371 | 2.38% |
| 字节控制流 | 10163 | 10160 | 0.03% |

新增独立 C 测试遍历全部 65536 个 int16 位模式，将转换结果纳入 FNV 型散列，并覆盖 int8/int16 到 int32 的混合运算和函数调用。Python 使用独立的定宽整数计算核对串口结果。新增测试和既有三角形/控制流共 256 个用例通过；新增测试固件 959 → 939 B，三角形/控制流固件 2366 → 2300 B。

三角形本轮时间为已有合格 Keil 对照 8570 tick 的 **121.02%**，仍未到 110%。混合位宽测试没有新建合格 Keil 性能分母，9.37% 仅表示相对 MX251 父版本的改善。

## 未采用的试验

**提前降低 16 位乘法。** 把编译器内建乘法调用提前变成原生 MIR 乘法，让分配器更早看到 MUL 约束。三角形固件仍为 2366 B，HEX 与父版本逐字节相同，已撤回。补丁与结果保存在研究目录，避免重复此试验。

**局部整数对象提升。** Keil 对照显示局部量大量使用寄存器及可覆盖的静态 DATA；MX251 使用可重入栈帧。试验在内联和地址折叠之后，将地址已不再被使用、只有完整整数读写的局部对象转换为 MIR 变量。三角形中 3 个对象、39 处访问可以转换。

首版暴露出候选选择规则的不连续：对象数降到零后，分配器采用另一套限制，选出 1108 B 的函数，放过了已有的 924 B 候选。继续沿用原有对象函数的搜索规则后，整个测试固件降到 2201 B，p080 降到 21431 B，CDC 仍为 4745 B。

但实板三角形为 10420 tick、字节控制流为 10306 tick，分别比本轮采用版本慢 **0.47%**、**1.44%**。结果值全部正确，收益却不足以支持直接并入。提升实现及分配选择试验均已撤回，补丁、源码、构建和实板结果保留在 `narrow-integer/scalar-promotion-trial.patch`、`wide_scalar_objects-trial.c.inc` 和相应 JSON 中。板上最后保留的是这份结果正确的试验固件，未执行恢复旧固件操作。

这说明后续应联合处理局部变量的活跃区间、复制合并及跨调用分配；只把栈对象换成一个长活期虚拟寄存器，收益会被新增搬运和保存抵消。既有选择性 ABI 研究也已证明单纯扩大寄存器传参并不普遍获益，不必重新做同一组试验。
