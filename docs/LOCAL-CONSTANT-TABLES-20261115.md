# 局部常量数组传播：2026-11-15

宽后端现在可以把小型局部数组的读取变成常量选择，消除数组初始化、栈存储、索引缩放和指针读取。识别依据是数组的值与用途，不按函数、工程、器件或 SDK 名称匹配。

| 用户函数 | 原 MX251 | 新 MX251 | Keil C251 | 原耗时/Keil | 新耗时/Keil |
|---|---:|---:|---:|---:|---:|
| callback_messy | 229 B | **146 B** | 71 B | 152.89% | **136.51%** |

该函数体积减少 **36.24%**，实物耗时下降 **10.71%**。6 字节局部回调表及其基址保存消失，循环内不再执行指针元素大小乘法和三字节指针读取。仍未进入 120% 体积线或 110% 耗时线。

用户测试固件由 **7063 B 降至 6981 B**，为 Keil 6124 B 的 **113.99%**。函数减少 83 B，整包净减少 82 B：链接布局变化使 `parser_clean` 的一条 `AJMP` 改为 `LJMP`，多占 1 B。其指令数量未变，其他用户函数的分类字节数未变。普通回调函数仍为 99 B。

## 通用实现

- 处理 2～8 个元素的局部标量数组，支持整数、数据指针及函数指针。数组不必声明 `const`，但每个元素必须只有一个已知常量初始化；该初始化必须在所有到达读取的路径上执行。
- 跟踪数组地址的派生和使用，要求地址只参与本数组寻址、读写。地址外传、后续修改、部分写入、volatile 数组不进入这条路径。
- 复用现有 CFG 支配分析，识别有界下标、元素大小乘法和移位；索引值必须在原直线执行片段内保持有效。保留真实内存取样，包括 volatile 下标读取。
- 新增独立的常量选择 MIR 和发射器，整数保持位宽，指针保持 24 位地址及零填充，包括整数转指针再转整数的初始化。
- 移除不用的数组和纯地址计算，重新布局其余局部对象、重新分配寄存器。选择仍比较完整函数的体积与成本。四元素有符号整数循环测试虽然从 117 B 试算为 90 B，但加权指令成本从 134 升至 144，因此保留原方案。
- 数组更大、下标范围未知、初始化不满足支配关系等情况继续使用原数组访问。已有 CODE 指针数组导入限制未在本轮扩展。

## 验证

- `check-local-constant-tables.py`：small/large × size/speed × ABI2/ABI4，共 **8 组通过**。两元素及八元素的整数表、数据指针表、回调表、指针常量转换、多个局部数组共存均覆盖。
- volatile 数组、循环修改、地址传给外部调用、字节别名部分写入、条件初始化、未知下标、截断后地址回绕，七类函数机器指令与上一版相同；已有 CODE 指针导入路径也保持相同。large 模型下原有 volatile 全局访问回退未扩大。
- 新增独立主机参考及板测脚本 `constant_table_fixture.py`。18 类 × 64 个组合项，每项组合 4 个字节输入，覆盖每类全部 256 个字节输入。ABI2、ABI4 各 **1152 项实物结果全部匹配 GCC 参考**。这组测试验证语义，不提供耗时比较。
- 用户压力测试 **63/63 编译单元通过**，三种目标描述的纯 C 对象一致。只有 `callback` 的 9 个对象改变，其他 54 个对象与上一版逐字节相同。
- 完整用户固件实物采集 **3678 帧、832 项，每项至少 4 次**，零结果错误、零计时溢出。最终编译器重建的 HEX 与已采集镜像 SHA256 完全一致，复用对应原始采样。
- 12 类用户工作负载中，全部 64 个输入达到 Keil 110% 耗时线的仍为 **9/12**。沿用同源 Keil 固件及同板采样，按实测时钟归一化；测量包含分发、工作负载和结果搬运，UART 在区间外，空控制不扣除。

本轮未重跑完整官方工程矩阵，未测 STC-IDE，不更新官方工程达线统计，也不代表完整工程耗时已经达线。
