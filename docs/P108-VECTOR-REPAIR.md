# p108 绝对中断入口修复

2026-11-13，实现提交 `b000611`。修正后的同一份输入，MX251 为 **1214 B**，Keil C251 为 **1432 B（84.78%）**，已进入 110% 体积线。运行时间比例未测。

## 原因与改动

原例程的 23 个扩展向量共用一个汇编出口，最终 `JMP 006BH`。对应 interrupt 13 的 C 处理函数已被注释，实际只有 UART1 超时中断 interrupt 4。`0xFF006B` 在 MX251 映像中没有代码，在冻结 Keil MAP 中位于 `main` 的指令内部。

本次在独立工程副本中，把 Keil 和 MX251 两种汇编输入的这一处出口同时改为 `RETI`。该例程 `DMA_UR1T_CFG`、`DMA_UR1R_CFG` 均为 0，未启用这些 DMA 中断，UART1 超时仍由原 C ISR 处理。这个空返回出口只适用于本例程未使用的扩展向量；实际启用某个扩展中断时仍应提供其处理程序。

MX251 编译链新增通用能力：识别绝对汇编中的独立 `RETI`，以及经过一层或多层 `LJMP` 到达 `RETI` 的入口。与原来的 C 向量入口一样，链接后核对原始跳转与返回字节。格式库和启动代码选择共享此检查。没有 SDK 名称、函数名或固定地址特判，编译器二进制沿用上一版，改动集中在运行库选择脚本。

原冻结 SDK、原始 75 项报告保持不变。修复副本的 C 文件没有修改；修正的汇编与原输入分别记录哈希。
