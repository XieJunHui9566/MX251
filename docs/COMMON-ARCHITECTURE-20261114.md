# 通用架构能力与 STC32G 优化结果

本轮将编译能力从器件的独立开关上移到架构配置。CPU 架构和 ABI 决定通用代码生成，器件配置描述内存、启动、SFR 和外设效果。SDK 算法保持原样，编译器二进制沿用当前核心，本轮改动位于正式构建链与 C251 兼容层。

## 结果

STC32G 全部 103 个 C 工程：97 个成功；修复原来的 8 个 MX251 构建失败。5 个 USB OMF 库工程和 1 个官方源码错误仍未完成。39 个纯 A251 汇编工程本轮未重跑，仍沿用此前未支持的结论。

新旧均成功的 89 项：290604 → 269457 B，减少 21147 B；89 项缩小、0 项相同、0 项增大。新增成功工程不混入该节省量。

| Keil C251 | 97 | 29 | 41 | 279281 / 217533 | 130.14% |

AI8051U 六个对照工程 p039, p070, p083, p105, p120, p123 分别使用旧核心和本候选重新编译；6/6 个 HEX 完全相同。本轮仅统计体积和编译结果，未测整工程运行时间。

## 实现

- TargetContracts schema 2 增加架构层；两种器件复用 mcs251-flat24-codeff 的 CODE 原生读取、对象地址能力与按程序生成的向量表。未来同架构目标自动继承，不需要复制优化开关。
- CLI/CMake 从目标注册表选择 profile，移除入口中两个器件名的白名单；SPH、外设位效果、启动与内存窗口仍由器件描述。STC32G 的 SPH=0x85 来自官方 STC32G.H，Keil 的正弦表读取也使用 MOV WR,@DR。
- 向量表按实际链接的 ISR 生成；保留跨文件、归档成员的 ISR 发现与芯片槽号上限。未使用的中间槽采用现有 compiler-default RETI，最高已用槽之后不再预留中断表；不再默认生成全槽停机桩。
- C251 兼容层沿共享标签跳转链解析中断转发，生成裸 ISR。7 个 DMA 工程不再由旧转换额外占据固定 HOME 地址。原始汇编和转换差异保存在 input-provenance.json；没有改 C 算法。
- 近跳转支持只有局部跳转、没有可转换函数调用的计划，修复空函数列表的 PowerShell 属性访问错误。

## 验证与使用

通用能力继承检查覆盖两个真实目标及一个独立名称的配置；另有跨文件中断发现与槽号上限、16 项近跳转选择、6 项页内跳转布局、数字/共享标签转发与 8 类不支持输入检查。真实工程最终向量字节和 HEX 哈希随构建记录核对。

## 下一处通用收益

对本轮最终 ASM/RST/HEX 做函数归因：61 个工程、86 个中断函数仍退回完整保存，其中 57 个阻点是 `mov @dpx,a`。这不是预计可删除的函数数或字节数；其中可证明属于普通 RAM 对象的写入才可释放保存。

| 例子 | 函数 | MX251/B | Keil/B | 差值/B |
| --- | --- | ---: | ---: | ---: |
| g013 | TIMER1_INT | 163 | 40 | 123 |
| g025 | UART2_INT | 158 | 53 | 105 |
| g031 | UART1_INT | 156 | 49 | 107 |
| g013 | DISPLAY | 176 | 94 | 82 |

优先把 EDATA 标量和数组的对象来源、偏移范围保留到旧后端与中断效果分析，使间接写入不再丢失信息；同时选择更短的原生访存。其次让已知不同对象的存取保留值复用，释放重复读取、商余数复用和地址生成优化。上述规则应按地址空间、对象和指令效果实现，不加入器件或 SDK 名称判断。

格式化库仍是另一类大项：g083 的格式串与参数宽度不一致触发完整库，g070 也有明显运行库开销。应继续从通用格式化实现与调用约定处理，不能通过改 SDK 格式串把结果计成编译器收益。

原始归因保存在本轮证据目录 `next-hotspots.json`、`isr-blockers.json`；函数字节来自最终指令，Keil 函数段可能含表数据。实现提交 `35a47d9`，分支 `codex/common-target-codegen`。
