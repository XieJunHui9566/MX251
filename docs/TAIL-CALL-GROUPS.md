# 尾调用组与定宽跳转表

尾跳转不压入新的返回地址，不能独立改变调用链上一个函数的返回方式。本次按尾跳转边的无向连通分量选择函数组：成员均满足寄存器参数约定，全部外部引用为有类型信息的直接调用，组内尾跳转目标可见。整组统一采用两字节返回地址；单独被调用的成员仍作为单节点组处理。

普通调用 ECALL→LCALL，普通尾跳转 EJMP→LJMP，返回 ERET→RET；后续页内选择继续把同页的调用和跳转缩短为 ACALL/AJMP。取地址、特殊入口、外部库尾跳转、未知间接跳转等使整个相连组保留原约定。

编译器为宽指令后端生成的跳转表补充元数据。构建器核对符号基址、分发表和四字节 EJMP 表项，保持表项宽度，只缩短普通指令。表项可以直接尾跳到组内另一个函数。此改动没有调整 switch 的索引计算或参数传递方式。

同时修正局部标号索引：`00101$` 等标号在不同函数内可以重复，选择器和最终地址核对现在使用函数作用域，避免把普通局部跳转误判为跨函数跳转。跨翻译单元的尾跳转按目标函数所在单元解析地址。

验证覆盖跨单元尾调用链、循环、固定宽度表项、重复局部标号、ABI2/ABI4、取地址成员和不完整调用信息。实板固件以两页代码覆盖跳转表、普通尾跳转、返回值、循环及未转换的间接调用，使用独立 Python 结果算法。
