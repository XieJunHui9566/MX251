# 栈地址直接写目标寄存器：2026-11-09

取栈参数或局部对象的地址时，宽后端原先用 DR16 计算后再复制到分配的指针寄存器。本次直接在该目标寄存器计算，省去最后一次 MOV。地址偏移、24 位指针掩码和动态栈深度计算沿用原实现；指针本身溢出时仍使用 DR16。生产代码仅修改 `wide_emit.c.inc` 的两处发射。

父版为 `2cfd200`。p080 TFT 通过正常 CMake 入口完整构建，small/speed、C251 位补兼容和默认调用反馈；叶函数反馈保持关闭。源码输入哈希一致，完整代码从 **23195 → 23161 B，减少 34 B（0.15%）**。相对同模型 Keil 的 18071 B 为 128.17%，本轮新增 120% / 110% 达标工程为 0。运行时间未测，没有操作硬件，也没有扩大整套 SDK 构建矩阵。

`check-wide-formal-address.py` 的 small/large × speed/size 四组均通过，每组消除 21 次地址中转复制；将父版对应序列合并后，整个编译单元的指令、标签和指示符与新版相同。八组指针/volatile 边界检查和现有 V0.0136 成本回归通过。旧测试要求压力函数必须出现 spill，但父版已有整数下沉优化会消除这些 spill；改为检查实际取址槽，原对象/溢出槽布局检查保留。可用 `--baseline <父版 sdcc.exe>` 重现逐指令对比。

## 本轮停止的两个方向

- 寄存器复制合并：首版使 p087 / p095 / p091 分别增加 12 / 14 / 10 B，p080 减少 20 B。原因之一是宽候选少使用一个寄存器后，原先更短的普通后端不再满足写寄存器集合条件。保留原分配寄存器集合后，p095 仅减少 2 B、p080 减少 28 B。收益不足，未合入。
- 增加 32 位溢出优先级：只编译 TFT 热点单元，`Fill_Triangel` 候选变大；`LCD_ShowChar` 候选少 24 B，但循环加权指令增加；三个字模函数各少 19 B，已有循环比较无法作出结论。没有被选中的候选，未合入，也未继续扩大机制或测试。
