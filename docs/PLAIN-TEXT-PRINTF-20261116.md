# 纯文本 printf 与标准 puts · 2026-11-16

本轮完成通用纯文本调用改写，并将标准 `puts` 源码接入现有运行库编译步骤。六项完整固件对照中五项缩小，一项增大，合计净减 307 B；g104 跨入 Keil 的 110% 体积线。p123 增大 22 B，因此本版保留为开发候选，没有替换默认基线，也不宣称所有程序都更小。

## 通用实现

MCS251 的 stack-auto 模式现可使用前端已有的 `printf("文本\n") → puts("文本")` 转换。调用必须只有一个字符串字面量参数、不包含百分号或内嵌 NUL、以换行结束，且返回值未被使用。声明须符合普通泛型字符指针的 stdio 接口；返回字符数、额外参数的副作用、动态格式以及非标准声明均保留原调用。其它目标的行为保持原样，`--nostdlibcall` 可关闭该转换。

转换让字符串指针走普通寄存器参数通道，函数末尾还可能采用尾跳转。它会新增 `puts` 链接成本，不能只按调用位置节省的指令计算收益。

标准库现有 `puts.rel` 为 102 B。用当前编译器重编同一份标准源码为 64 B，并直接使用原生指针读取。现有闭合格式运行库生成步骤发现实际链接的是已核对的标准 libsdcc `puts.rel` 时，将原始 `device/lib/puts.c` 一同编译；公开 ABI2、字符输出和 EOF 处理保持原样。应用自定义的 puts（包括应用归档中的成员）不由此替换。三个既有私有 ABI 候选的编译轮数没有增加。

实现不含工程编号、SDK 函数名、器件型号判断。编译器按 C 语义转换，运行库按已链接的标准库成员选择源码。

## 检查与边界

- 14 组目标编译：small/large、普通 ABI/ABI4 调用方、开启/关闭标准库转换；核对实际调用目标、常量字节和共享字符串。
- 覆盖换行、CRLF、多行文本、返回值使用、百分号、动态指针、内嵌 NUL、额外参数副作用、非标准声明、缺少 puts 声明和非 stack-auto 模式。
- 库函数原始源码未修改；本轮未执行实板输出或计时。减少了格式解析和参数压栈路径，不将其直接换算成运行时间百分比。
- 最后一次修改只将 puts 提供者条件收窄到标准 libsdcc。六项构建记录选中的提供者前后一致；实际构建脚本快照单独保存，没有为不影响这六项的条件再做整包重编。

现有 203 项记录中，54 项有 305 个存活的纯文本 printf 调用，其中 271 个符合“无百分号且以换行结束”的字面量形态。这只是候选统计，尚未对全部调用证明返回值未使用或全部声明条件成立，也不是 54 项收益承诺。

## 下一处优先级

标准库中仍有旧后端生成的基础函数。原样源码用当前 small + stack-auto + ordinary-wide + size 编译，得到以下单元结果：

| 标准库成员 | 现有目标代码/B | 当前编译器/B | 少/B |
| --- | ---: | ---: | ---: |
| `__memcpy.rel` | 207 | 72 | 135 |
| `_memset.rel` | 141 | 66 | 75 |
| `strlen.rel` | 96 | 43 | 53 |

这三项尚未接入候选库，未计入任何完整固件收益。下一步应优先统一重建基础标准库并测量真实链接结果，复用已完成的通用寻址/算术优化，而非继续逐个缩短提示文本调用。此方向可直接服务普通用户写出的内存复制、清零和字符串处理代码。
