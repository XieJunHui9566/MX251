# 约 140% 工程：下一步优化定位

2026-11-10，基于统一 75 项结果、提交 `1dfb3ac`。本轮按 **130%～150%（含边界）** 筛选，共 13 项；读取全部 75 项的最终 ASM/RST/HEX 和 Keil MAP，再对已有无符号除法路径做 7 项独立试编。编译器与 SDK 源码均未修改。数据及产物指纹见 [证据](focus-140-percent-evidence.json)。

## 1. 整函数回退：覆盖面最大的结构问题

75 项中有 **90 个函数、17425 B 当前函数体**，记录了 `ordered-asm-core-state-write`。全部 75 项均有命中；13 项重点工程中命中 16 个函数、3540 B。多数出现在初始化中的 EAXFR 等设置。

当前 `wide_ordered_asm.c.inc` 把目标允许的普通 SFR 位操作作为有序节点导入，但 `wide_ordered_contract.h` 明确排除改变存储映射、寄存器或执行状态的操作。一条此类操作就会令整个函数采用旧后端，后续的结构体索引、宽算术和调用也一起失去宽后端优化。

这解释了 p074、p103、p122 的 main 为什么明显偏大。特别是 p103 的结构体数组地址与 word 读写仍出现逐字节地址构造，而 Keil 使用 word 寄存器计算和访存。

接续方向：在 MIR 中区分“有寄存器效果的操作”和“改变存储映射的边界”，描述效果并限制跨边界搬移，使边界两侧仍能优化。逐步替代整函数回退。EAXFR 确实改变访存含义，应给它对应语义；单纯加入普通 SFR 白名单不是这个问题的解法。规则按指令效果、目标能力和 IR 建立，不按 SDK、函数名或工程 ID 建立。

17425 B 是受影响函数体积，**不是预测可节省量**。另外还有 54 个函数因普通位能力未覆盖回退、58 个函数因地址空间/对象约定回退，完整分类保留在证据中。这进一步支持先完善后端覆盖机制。

## 2. 无符号除法：已测到 554 B 收益，混合宽度仍是障碍

统一版本中共有 12 个工程、14 个函数在除法导入处回退。首次失败涉及 8 个 16 位函数和 6 个 8 位函数。16 位实现已经存在，由研究开关 `MX251_WIDE_UNSIGNED_DIVISION=1` 控制；默认包没有启用。

本轮对涉及 16 位的 7 个工程，使用同一编译器、原样源输入和原构建选项，仅增加这个开关做完整编译/链接：

p039/p059 的 `get_temperature` 指令从 544 B 变为 418 B；整工程各少 256 B，包含运行库等联动变化。p059 的试编体积进入 120% 线，p128 进入 110% 线。此表是独立试编，尚未并入统一配置，也没有新增实板功能或运行时间成绩。

**p011/p049 不变的原因已经定位：**第一个 16 位除法接受后，后面的 8 位 `/ 10` 又触发整函数回退。因此“只打开 16 位开关”不能解决它们的 Display。当前 Display 的 220 B 中有 128 B PUSH/POP 指令，用于算术值运输；Keil 的 94 B 版本用 word 寄存器承接中间值。Keil 也有重复除法，首要差别是寄存器运输和后端覆盖，而非改写十进制算法。

建议先让无符号 8/16 位除法、取余及窄化结果共同走原生寄存器路径，再做代表性的算术结果验证和这 7 项编译对比。随后统一合入并更新整批表，避免把单工程试编最小值拼成发行配置。

首次通过 CMake 入口传环境变量时，入口按设计过滤了研究变量，7 项 HEX 全部与基线相同。有效试编随后直接调用现有 `Build.ps1`，完整命令、环境和结果保存在 `focus140/division-probe/`，并以 ASM 中实际导入结果确认开关生效。

## 3. ISR 保存：已有局部实现，扩展对象应是调用与间接访问

全 75 项中，63 项含 C ISR，共 109 个；入口/出口 PUSH/POP 指令合计 **4768 B**。30 个 ISR 有直接调用；现有叶 ISR 优化已作用于 22 个函数。13 项重点工程中有 27 个 ISR，保存/恢复指令合计 996 B，同名 ISR 对比的净差额为 844 B。

最清楚的实例是 p146：`KeyResetScan` 本体 44/43 B，调用它的 `timer0_int` 却是 64/16 B。MX251 按整组保存 R0..R31 等现场，Keil 只保存 DR8、WR6、PSW1。MX251 的 ISR 中有 56 B 保存/恢复指令。

另一个共同情形是 DMA 与串口 ISR。现有 `gen_leaf_isr.c.inc` 已能缩减无调用、直接访存的 ISR；遇到 `mov @dpx,a`、`mov a,@dpx` 等间接访存便退出。这直接命中 p103、p122、p133。p032 的两个 ISR 没有普通调用，但仍各有 60 B 保存/恢复。

接续方向：复用最终指令效果和普通调用已有的实际写集合，覆盖 ISR 的间接访存与直接调用闭包，按真实改写寄存器生成现场保存；处理相应栈槽偏移和寄存器组。已有普通调用反馈不能直接当成异步中断现场规则，但可以共享分析事实。无需重做已经奏效的简单叶 ISR 优化。

4768 B 和 996 B 是已发射的保存指令总量，不能全部删除；844 B 也包括 ISR 本体差异。它们用于排序工作，最终收益以完整镜像计。

## 4. 固定启动成本与库成本要分别处理

p001 应用只多 17 B，镜像却多 76 B；余下 59 B 来自启动等公共部分。MX251 的 HOME/GS* 共 80 B，另有 4 B 启动钩子；Keil 对应非应用部分共 25 B。p003 应用合计仅多 7 B，剩余差额为 95 B。小工程的高比例并不等于循环或算术生成差同样比例。

当前空初始化裁剪特意重现原启动代码退出时的 DPX、DR4、DR12 和标志状态，即使初始化区为空，也保留一些寄存器装载。下一步可建立 C 入口实际需要的状态并按已链接对象生成启动代码，连同未使用的向量/跳板一起计算成本。这与上一轮恢复裁剪生效不同，是进一步降低启动自身成本。

p097/p103 还应单列格式化库：CSEG 扣除应用指令分别余 1232/1001 B，其中各含 4 B 启动钩子；Keil `?C?LIB_CODE` 分别为 851/768 B。扣掉这 4 B 后的余量差为 377/229 B，不能归因于 main 或 ISR。现有格式化专用运行库已经生效，后续应关注其通用参数读取、整数转换与寄存器运输，而非再次恢复开关。

p122 的 LCD_Init 和 KeyScan 已选宽后端，仍分别多 239/146 B，属于宽后端内部的后续优化样本。本轮没有把所有差距都归为回退。
